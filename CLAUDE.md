# MythScribe — Claude Code project guide

MythScribe is a local-first desktop novel-writing app (Scrivener-style organizer + distraction-free
editor + story tagging + AI that understands the author's manuscript while keeping the author's
voice, intent, and control). It is also a business: free app, bring-your-own-key AI, and a paid
MythScribe Cloud subscription.

## The one rule

**`FEATURES.md` is the single source of truth.** Features have IDs (`F-3.2`), status checkboxes,
and a milestone order. Build only what is in it; tick a box only after verification. Update the
spec in the same change when reality changes.

`PLAN.md` holds the reasoning: AI design (voice, intent, control), AI architecture, business model,
risks, roadmap. Read it before working on anything under `FEATURES.md` §2.5, §2.14, or §2.15.

The original prototype was deleted on purpose (git tag `v0-legacy`). Do not resurrect its code.
`FEATURES.md` §5 lists its mistakes; do not repeat them.

## Workflow

- `/feature F-x.y` — implement one feature end to end (plan → build → review → verify → tick the box).
- `/audit` — reconcile `FEATURES.md` statuses with the code.
- Work in milestone order (`FEATURES.md` §6). Launch-line features first; anything past the line waits.
- Small, complete slices. A feature is done when it works in the running app, passes the gates, and its checkbox is ticked.
- Before touching the schema, the IPC contract, prompts, or more than ~8 files, show the plan and wait.

## Development standards

- **Types are the contract.** No `any`, no `as unknown as`, no `@ts-ignore`. IPC channels are defined once in `src/shared/ipc/` with zod schemas and typed on both sides.
- **Tests with the code.** Data layer, editor commands, prompt builders, and post-processors get unit tests in the same change. Every feature with a UI path gets an e2e step in the smoke test or a documented manual check.
- **One owner per piece of state.** Normalized stores; update the changed record, never reload the world.
- **Reuse before you write.** Look for the existing helper, hook, or pattern first. Parallel implementations are a review failure.
- **No dead ends.** No stubs, no "coming soon", no `TODO` standing in for required behavior, no `console.log` left behind, no native `alert`/`confirm`/`prompt`.
- **Migrations are numbered and tested.** Never edit a shipped migration.
- **Errors are handled where the user can act.** Surface AI/provider errors with the cause (no key, bad key, rate limit, quota, policy refusal) and the next step.
- **Keep dependencies boring and few.** Pin versions. Justify any new dependency in the commit message.
- **Commit messages** are imperative and reference the feature ID (`F-3.2: autosave with debounce`). Never commit `.env` or keys.

## AI feature rules: author control and token efficiency

Every AI feature is a cost line on the Cloud plan and a trust line with the author. These rules
apply to all of `FEATURES.md` §2.5, §2.14, §2.15 and are checked in review.

**Author control**
1. AI output is always a `Proposal`; nothing enters the manuscript without an explicit accept (F-14.5). Accepted text carries provenance (F-14.6).
2. Every prompt that generates prose includes the voice profile, the scene brief, and retrieved exemplars (F-14.1–14.3); every generated proposal passes the fidelity check (F-14.7) before display.
3. Respect the AI dial and per-feature toggles (F-14.4). Installs at Off. A feature must not send text the data-sharing panel does not list.
4. Grounded answers only: Story Intelligence answers cite manuscript passages or say "not found" (F-5.7). Critique cites a passage for every claim; no uncited praise (F-14.8).

**Token efficiency** (measure with the usage ledger, F-5.14; budgets are per feature)
1. **Tiers, not names.** Request `fast` or `strong` (F-5.11). Ghost text, tags, summaries, embeddings, and classification use `fast`. Only Author mode, critique, and queries may use `strong`.
2. **Retrieve, do not dump.** Never send the whole manuscript. Context is built from scene summaries (~100 tokens each), entity sheets, and the top-k retrieved chunks within a fixed budget (default: 3 full scenes + 10 summaries, hard cap per feature). Recent text at the caret is capped (~500 characters for ghost text).
3. **Stable prefix first.** Order prompts as: system rules → voice profile → story bible → task-specific context → user turn, so provider prompt caching applies to the stable part. Do not interleave dynamic text into the prefix.
4. **Cache locally.** Identical (feature, prompt version, context hash) requests return the cached proposal. Summaries and embeddings are invalidated by content hash, not by time.
5. **Trigger discipline for ghost text.** Minimum idle interval, minimum new characters typed since the last request, no request while a proposal is pending or visible, per-day cap. Off at dial ≤ 1.
6. **Short outputs, structured where possible.** Set `max_tokens` per feature (ghost text ≤ 60; tags ≤ 200; summaries ≤ 150). Use JSON/structured output for tags, summaries, and critique so parsing is exact and retries are rare.
7. **Batch the background.** Indexing (summaries, embeddings) goes through the job queue (F-5.13) and uses the provider batch API when available; never block typing; coalesce edits so a scene is summarized once per burst.
8. **Count before you send.** Estimate tokens locally; if a request would exceed its budget, trim context by priority (drop far summaries, then exemplars, then recent text) rather than failing or overspending.
9. **Prompts are compact and versioned** (F-5.12): no restated instructions, no examples the retrieval already supplies, no reasoning dumps. Every prompt change runs the eval harness and reports token delta and fidelity delta in the PR.
10. **Cost is visible.** Each proposal records model, tokens in/out, and cost; Settings shows the running total. A feature that cannot report its cost is not done.

**Token efficiency in this repo (for Claude Code itself)**: do not re-read files already in context; grep before reading; delegate broad searches to `Explore`; keep agent prompts to the feature ID and a plan file path; one implementer per feature; the full gate suite runs at most twice per feature (see the global Delegation section), targeted checks otherwise.

## Quality gates (must pass before a feature is "built")

- `npm run typecheck` — zero errors
- `npm run lint` — zero warnings
- `npm run test` — unit tests for the data layer, editor commands, prompt builders, post-processors (vitest runs 4 reused workers without per-file isolation, see `vitest.config.ts`; every test file must reset module state such as Zustand stores and the IPC client in `beforeEach`, and stores with debounced writes in `afterEach` too)

## Stack (approved)

| Concern | Recommendation | Why |
|---|---|---|
| Shell | Electron + electron-vite + TypeScript | Native file dialogs, SQLite, fullscreen; Windows builds already worked |
| UI | React 19 | Known quantity; editor ecosystem |
| Editor | **Tiptap (ProseMirror)** instead of Slate | First-class custom inline nodes and a Suggestion extension for inline `#tags` and ghost text; Slate caused most v0 pain (`FEATURES.md` §5.1) |
| State | Zustand (normalized stores per entity) | Ends the reload loops from v0 |
| Styling | Tailwind v4 + CSS variables for design tokens | Enables themes (F-7.8); ends inline-style sprawl |
| Data | better-sqlite3 + Drizzle ORM + numbered migrations; sqlite-vec for embeddings | Typed queries, real migration history (F-8.2), one project folder |
| IPC | One typed contract in `src/shared/ipc/` with zod validation | Fixes the `window.api as any` drift |
| AI | Provider interface in main; **OpenAI SDK as default adapter**; Cloud adapter speaks the same interface to our proxy; keys in Electron `safeStorage` | F-5.1, F-15.1, F-15.4 |
| Cloud | Cloudflare Workers (Hono) proxy + Lemon Squeezy webhooks + magic-link auth | Serverless, no content storage, cheap at zero users |
| Tests | Vitest + Testing Library; Playwright for Electron e2e | v0 had zero tests |
| Tooling | ESLint (flat config) + Prettier; electron-builder; Azure Trusted Signing | Keep what worked; signed builds from first public beta |

Alternatives considered: Lexical (fine, smaller mention ecosystem); Tauri (smaller binary, weaker Node/SQLite story here); keeping Slate (rejected).

## Architecture (as built in M0)

- `src/shared/ipc/contract.ts` — the IPC contract: every channel's zod input/output, main→renderer events, error codes. Add a channel here first; both sides are typed from it.
- `src/main/ipc/registry.ts` — `register(channel, fn)` validates input and wraps errors; throw `AppError(code, message)` from handlers. `emit(windows, event, payload)` pushes events. Handlers live in `src/main/ipc/handlers.ts`.
- `src/main/db/` — `schema.ts` (Drizzle), `migrations/` (generated SQL, numbered, committed, never edited), `migrate.ts` (runner with `schema_migrations` table), `connection.ts` (`openDatabase` applies pragmas and migrations).
- `src/main/project/` — `projectStore.ts` creates/opens the `<Name>.mythscribe/` folder; `manager.ts` owns the single open project and notifies on change.
- `src/main/project/seed.ts` — pure `seedSkeleton(format)` (3 sections + Part/Chapter/Scene skeleton, 17 rows) and `seedSettings(format)`; run inside `createProject`'s transaction. `src/main/tree/treeStore.ts` — `insertNodes`, `listNodes` (ordered parent, position, id; roots first), `toTreeNode`; `TreeDb` accepts the orm or a transaction handle.
- `src/shared/labels.ts` — `SectionType`/`HierarchyLevel`/`NodeKind` enums (one owner; Drizzle columns use the same tuples), `sectionLabel(format, section)`, `levelLabel(format, level)`, `skeletonSummary(format)`. Section rows store the canonical key (`front`/`manuscript`/`end`) as `title`; the UI must label roots via `sectionLabel`, never `title`.
- `src/shared/editorSettings.ts` — zod `EditorSettings` and `defaultEditorSettings(format)` (F-3.6 defaults); stored in the project `settings` table under key `editor` as JSON.
- `src/main/appState/` — app-level (not per-project) state in `<userData>/app-state.json`: `appStateStore.ts` reads lazily, validates with zod, writes atomically; `recents.ts` holds the pure recents list operations. Recents are recorded on the `manager.onChange` hook in `handlers.ts`. F-7.9 window state belongs in the same file. `MYTHSCRIBE_USER_DATA` overrides the userData directory (used by e2e for isolation; the single-instance lock also lives there, so e2e and `npm run dev` can run concurrently).
- Autosave (F-3.2, F-3.7): `src/renderer/features/editor/autosaveStore.ts` is the one owner of the machinery: `createAutosaveStore<T, R>({ empty, get, save, onSaved?, delayMs? })` returns `{ useStore, reset }` with `docs[id] = { content, dirty }`, `load/unload/edit/flush/saveNow/clear`, per-id debounce timers and load tokens, pending jobs keyed per id, one serialized write queue, retry after failure unless a newer edit replaced the job, and its own pending-save registration (first load) and unregistration (clear/reset). `documentStore.ts` (`useDocumentStore`, `resetDocumentStore`, `onSaved` merges the word count into the tree) and `notesStore.ts` (`useNotesStore`, `resetNotesStore`) are its two instances. Notes: `src/main/document/notesStore.ts` (documents and folders; section roots refused by `parentId === null`; shares `parseStoredTiptap` with the document store); `NotesEditor.tsx` takes only `id`; `NotesPanel.tsx` (toggle button in both toolbars' `right` slot, resizable handle with `role="separator"`, width clamped in-file); its open state and width live in the layout store (F-7.2); `App.tsx` `MainPane` renders it beside the editor for documents and folders.
- Sidebar tabs (F-7.3 shell): `src/shared/sidebarTabs.ts` holds the zod `SidebarTabId` enum (all seven ids, schema-stable; `Layout.sidebar.tab` persists the active one); `src/renderer/features/shell/sidebarTabs.ts` is the static registry (`SIDEBAR_TABS`, Manuscript only until later features append their entry) and `SidebarTabs.tsx` the ARIA tab bar + tabpanel; `ManuscriptTab.tsx` composes the tree and the create bar. A persisted id with no registered tab falls back to the first tab at render. `Layout` requires the tab (so the IPC input and output types match); `StoredLayout` in `src/shared/layout.ts` is the lenient reader the app-state file uses, defaulting a pre-F-7.3 file to Manuscript.
- Tags (F-4.1): `src/shared/tags.ts` is the one owner of the seven `TAG_CATEGORIES` (camelCase keys), `TAG_CATEGORY_LABEL`, `DEFAULT_CATEGORY_COLOR`, `HEX_COLOR`, `TAG_NAME_MAX`, and `toTagName` (kebab-case; letters and digits of any script are kept, so "Zoë" stays "zoë"). Schema: `tag` (name unique after normalization; `parent_id` self-reference, `ON DELETE SET NULL`) and `document_tag` (node↔tag link, unique pair, cascades from both sides; empty until F-4.4/F-4.6 write it) in migration `0002_tags`. `src/main/tag/tagStore.ts` mirrors the tree store: `listTags`, `getTagWithUsage`, `createTag`, `updateTag` (partial patch; cycle check walks `parentId` up), `deleteTag`; `usageCount` is derived with a `COUNT` join, never stored. Channels `tag:list`/`tag:create`/`tag:update`/`tag:delete`; errors `VALIDATION` (empty after normalization, self/descendant parent), `ALREADY_EXISTS` (name collision), `NOT_FOUND`. `migrate.test.ts` hard-codes the bundled migration count, so every new migration bumps it.
- Tag Manager (F-4.2): `src/renderer/features/tags/tagStore.ts` is the renderer owner of the bank (`byId`/`ids` ordered by name then id like `tag:list`; generation-guarded `load` on project open and `clear` on close from `App.tsx`, the tag load never blocks the tree; `create`/`update`/`remove` await main and merge the returned row, never re-list; `resetTagStore()` in tests). A tag created through the raw bridge (e2e) is invisible to the store until the next load. `TagsTab.tsx` composes the category strip (ARIA tablist over `CATEGORY_FILTERS` from `categoryFilter.ts`, where `'all'` is a UI-only filter and `defaultCategoryFor('all')` is `custom`), the search, `TagList.tsx` (`role="list"` of button rows; the color dot is the one inline style), `TagForm.tsx` (keyed on the filter so category and color re-default; a hand-picked color survives a category change), and `TagDetail.tsx` (labels stacked above controls so the sidebar minimum never overflows; inline rename keyed on the name so the field re-syncs to the kebab-cased result; color drag steps coalesce to one write in flight plus the latest pick; delete via `dialogs.confirm` danger). Filter, query, and selection are component state. No nesting UI (`parentId` is never sent). The create form's bottom row wraps so the sidebar minimum (15 %) never overflows; check new sidebar content at that width in a 1024 px window (tabpanel `scrollWidth` vs `clientWidth`; the resize handle deliberately straddles the border, so measure the panel, not the `aside`).
- Tag templates (F-4.3): `src/shared/tagTemplates.ts` is the one catalogue (`TAG_TEMPLATE_IDS`, `TAG_TEMPLATES`: Standard Fiction, Mystery, Fantasy, Sci-Fi, each 4–8 kebab-case tags per non-custom category, colors always the category default). `loadTagTemplate` in the main tag store is one transaction that reuses `insertTag`, skips by normalized name across the whole bank, and returns `{ created, skipped }` in template order through `tag:loadTemplate`. The renderer store's `loadTemplate` merges `created` in one `set`; `TemplateLoader.tsx` (select + Load, above the search in the list view only) confirms via `dialogs.confirm` and toasts the counts.
- Document tag bar (F-4.4): `src/main/tag/documentTagStore.ts` (`listDocumentTags`, `addDocumentTag`, `removeDocumentTag`; idempotent, transactional, documents only via the node row's `kind`, return the tag with its fresh `usageCount`) behind `documentTag:list`/`add`/`remove`. Renderer: `src/renderer/features/tags/documentTagStore.ts` owns `tagIdsByNode` (per-node load tokens, cleared on project close); `add`/`remove` merge the returned tag into the bank (`useTagStore.merge`, re-sorts only on a name change) before splicing the ids, so the Tags tab's counts move without a reload and chips always render the bank's record (rename/recolor shows at once). `TagBar.tsx` (`role="region"` "Tags", collapse toggle, chips with `Remove <name>`, bottom `ResizeHandle`) and `TagPicker.tsx` (searchbox + listbox of unassigned tags, ArrowUp/Down, Enter links, Escape/outside click closes, closes after one pick) mount only in the single-document view (`DocumentEditor` with its own toolbar), never in stacked regions. `Layout.tagBar = { open, height }`: height in px, zod floor `TAG_BAR_MIN_HEIGHT` (100), the 60 vh ceiling clamped by `clampTagBarHeight` at drag time and `max-h-[60vh]` at render; `StoredLayout` defaults it for old app-state files; `layoutStore` has `toggleTagBar`/`setTagBarHeight`/`resizeTagBarBy`. `ResizeHandle` supports `top`/`bottom` (horizontal, `aria-orientation`). The editor surface (`.ms-editor`) is a flex item that fills its scroll container (no viewport-relative min-height), so chrome above it never forces a scrollbar; stacked regions keep their own `6em` floor.
- Scene metadata (F-4.5): `src/shared/sceneMeta.ts` (zod `SceneMeta` `{ location, pov, timeline }`, `EMPTY_SCENE_META`, lenient `parseStoredSceneMeta`) stored as JSON in the existing `node.scene_meta` column, no migration. `src/main/tree/contentTarget.ts` `requireContentTarget(db, id, what)` is the one "any node but a section root" rule shared by notes, scene metadata, and document tags (so chapters and parts carry tags and metadata too). `src/main/document/sceneMetaStore.ts` behind `sceneMeta:get`/`sceneMeta:set`. Renderer: `sceneMetaStore.ts` is the third `createAutosaveStore` instance (debounce, flush, pending-save registration for free); `MetadataPane.tsx` (`role="group"` "Scene metadata") loads per node on mount and unloads on unmount, fields disabled until the load lands; `SuggestInput.tsx` is the combobox (label + input `role="combobox"`, listbox of names starting with the text, ArrowUp/Down, Enter fills, Escape/blur close; free text allowed) fed by the bank's setting tags (Location) and character tags (POV). `TagBar.tsx` shows the pane only for a node with a hierarchy level, behind `layout.tagBar.split` (fraction 0.3–0.7, `TAG_BAR_SPLIT_LIMITS`, default 0.4, its own `.default` inside `StoredLayout`'s tagBar schema so a `{ open, height }` file still loads; the drag is measured against the pane row's width via `resizeTagBarSplitBy`). `StackedEditor` mounts the bar once at the top for the folder itself (also for an empty folder). Tests that enumerate stacked document regions filter `getAllByRole('region')` to `<section>` elements, and the e2e uses `section[aria-label]`, because the bar is a region too.

Right-click on a token opens the manuscript `ContextMenu` with Remove (node only; the link stays) and Open in Tag Manager (opens the sidebar, `setSidebarTab('tags')`, `useTagStore.requestSelection(id)`, which `TagsTab` consumes once and clears). Known gaps: Ctrl+Z after an insertion leaves the link; a token pasted into another document is counted there but not linked; Edit on the token menu is deferred.
- AI provider and keys (F-5.1): `src/shared/ai.ts` is the one owner of `AiProviderId`, `Tier`, `DEFAULT_MODELS` (`fast: gpt-5.4-mini`, `strong: gpt-5.4`; F-5.11 turns it into a setting), `maskKey`, the `AiErrorCode` taxonomy (`NO_KEY | INVALID_KEY | RATE_LIMIT | QUOTA | NETWORK | PROVIDER`), `AI_NEXT_STEP` copy, and the `AiStatus`/`AiTestConnectionResult` shapes. `src/main/ai/providers/types.ts` is the generic `Provider` interface (`complete`, `stream`, `testConnection`, results carry `usage`) plus the `AiProviderError` class per code (SDK error on `cause`, fixed copy in messages, never the key); `openai.ts` is the only file importing `openai` (`buildOpenAiProvider(key, { fetch? })`, Chat Completions with `max_completion_tokens` and JSON mode, `maxRetries: 0`, `testConnection` = `models.retrieve` on the fast model, `mapOpenAiError`: 401 → INVALID_KEY, 429 + `insufficient_quota` → QUOTA, other 429 → RATE_LIMIT, connection → NETWORK, else PROVIDER with the status). `src/main/ai/keyStore.ts` (`AiKeyStore`) keeps `<userData>/ai-keys.json` `{ version, keys: { openai: <base64 ciphertext> } }` via `safeStorage` (atomic write, lenient read; a corrupt file reads as no key); `encryption()` is `os | plain | none`. `src/main/index.ts` calls `safeStorage.setUsePlainTextEncryption(true)` on Linux so a keyring-less box (this WSL machine) stores the key obfuscated and the AI tab warns; Windows/macOS use the OS store. `src/main/ai/registry.ts` (`AiProviderRegistry.get()`) rebuilds the client only when the decrypted key changes. Channels `ai:getStatus` (`hasKey`, masked `hint`, `encryption`), `ai:setKey`, `ai:clearKey`, `ai:testConnection` (expected failures come back as data with `code` and `nextStep`; only unexpected errors throw). The plaintext key exists only in main. Renderer: `src/renderer/features/ai/aiStore.ts` (`load/setKey/clearKey/test`, `resetAiStore()`) and `AiSettingsTab.tsx`, registered as the AI tab in `SETTINGS_DIALOG_TABS`. Tiers (F-5.11): the mapping is the app-state field `models` (`AiModels`, enum-keyed per provider, defaulted from `defaultAiModels()` so old files load; `TIER_USE` holds the per-tier hint copy, all in `src/shared/ai.ts`); the registry hands the cached provider a live `resolveModel(tier)` closure over `appState.get().models`, so `ai:setModels` applies on the next request without a rebuild; `AiStatus.models` carries the effective map; the AI tab's Models group commits on blur/Enter (blank or unchanged writes nothing, a refused save reverts and toasts) and its Reset is disabled at the defaults. - AI request path (F-5.14): every AI feature calls `runAiRequest(deps, input)` in `src/main/ai/request.ts` (pure over injected deps; `buildAiRequestDeps` binds the open project's db, the registry, and app state). Order: clamp `maxTokens` to `FEATURE_BUDGETS[feature]`, refuse an input estimate over `FEATURE_INPUT_BUDGETS` with `BUDGET`, refuse when the day's tally would exceed the cap (a cap of 0 pauses AI, cached answers included), cache lookup by `cacheKey` (feature, prompt version, model, json mode, context hash, messages), provider call, `priceFor(model)` (unknown → cost 0, `priced: false`; `MODEL_PRICING` in `src/shared/ai.ts` is the one owner), ledger row, cache write with the 500-row eviction, tally update. Tables `ai_usage` and `ai_cache` (migration `0003_ai_usage`) in the project db via `usageStore.ts` and `cacheStore.ts`; the daily cap and today's tally (`AiUsageState`, local-day rollover in `dailyCap.ts`) live in app state so the cap holds across projects. `AiFeature` (`ghostText | tags | summary`; extend it when a feature lands), `estimateTokens` (chars/4), `DAILY_CAP_*`, and `AiUsageSummary` are in `src/shared/ai.ts`; `src/shared/aiThrottle.ts` `shouldTrigger` is the ghost-text trigger discipline for F-5.3. The F-14.4 dial gate belongs to each caller, not to `runAiRequest`.
- Settings dialog (F-7.5): `src/renderer/features/shell/settingsDialogTabs.ts` is the tab registry (`SETTINGS_DIALOG_TABS`, Editor only; F-5.1 appends the AI tab, never a placeholder) and `SettingsDialog.tsx` the modal (role `dialog`, ARIA tablist like `SidebarTabs`, Escape/X/backdrop close, initial focus on the active tab, no Tab trap, same as `DialogHost`). It is not routed through `dialogStore` (whose modals are confirm/prompt-shaped). `SettingsButton` in `App.tsx` owns the open state, the Ctrl/Cmd+, `keydown` listener, and the dialog mount; it renders only while a project is open, so the shortcut cannot fire on the welcome screen. The active tab is local state, reset on open.
- Layout (F-7.2): `src/shared/layout.ts` owns the panel limits (`LAYOUT_LIMITS`), the zod `Layout` (`sidebar`/`notes` with `open` and `size` as fractions of the window width), `defaultLayout()`, and the clamps (`clampPanel`, `clampForEditorMin`, which keeps the editor at 30 % by clamping the dragged panel). App state stores it (`layout` field, defaulted so old files load); `layout:get`/`layout:set` read and write it. `src/renderer/features/shell/layoutStore.ts` is the renderer owner (loaded at app start, optimistic with one debounced write, registered with the pending-save registry; `resetLayoutStore()` in tests); `ResizeHandle.tsx` is the one drag handle (`role="separator"`, aria values in percent, px deltas that callers turn into fractions); widths render as `vw` so panels follow window resizes with no listener. The sidebar toggle lives in the top bar; the notes toggle in the editor toolbars.
- `src/renderer/features/project/pendingSaves.ts` — the pending-save registry: `registerPendingSave(flush)` returns an unsubscribe; `flushPendingSaves()` runs every flusher and rethrows the first failure. The project store awaits it before create/open/close and in `closeWindow()`. F-3.2 autosave registers here.
- Window close and quit: with a project open, main prevents the window `close`, emits `window:close-requested`, the renderer flushes and invokes `window:close`, and main closes the project and windows. `manager.close()` runs on `will-quit` (not `before-quit`) so the database outlives the flush. A failed flush leaves the window open with a toast and invokes `window:close-cancelled`, which resets main's `quitRequested` so an abandoned Cmd+Q does not make the next plain window close quit the app (macOS; manual check only, the e2e does not drive Cmd+Q).
- `src/main/lifecycle.ts` — `installSingleInstance` requests Electron's single-instance lock and focuses the existing window on a second launch; `index.ts` quits when the lock is refused.
- `src/main/project/legacy.ts` — `isLegacyDatabase` opens a database read-only and detects the v0 layout (`documents` table, no `node` table); `locateProject` in `projectStore.ts` uses it so a v0 file is refused with a clear message instead of being migrated by accident.
- `src/preload/index.ts` — exposes `window.mythscribe` (`invoke`, `on`), restricted to contract channels. Sandbox and context isolation are on.
- `src/renderer/lib/ipc.ts` — `ipc().invoke(channel, input)` typed client that validates outputs; `setIpcClient` for tests.
- `src/renderer/features/manuscript/` — `treeStore.ts` is the one owner of tree state: normalized `byId`/`childrenOf`/`rootIds`, derived `sectionOf` and `wordCountRollup` (rebuilt once per `load()` from `tree:list`), plus `selectedId` and in-memory `collapsed`. F-2.2–2.4 mutate it by updating the changed records, never by reloading the world. `ManuscriptTree.tsx` is an ARIA tree (roving tabindex, arrow keys); sections are labelled via `sectionLabel` and are not selectable; front/end-matter documents carry `data-matter` and the gold `text-matter` color. Per-level colors are tokens (`--ms-level-*`, `--ms-matter`) so themes (F-7.8) can override them. `App.tsx` loads/clears the store on project open/close and renders the fixed-width sidebar + main pane (F-7.2 adds resizing).
- Tree mutations: main validates structure inside a transaction in `src/main/tree/treeStore.ts` (`createNode`, `renameNode`, `duplicateNode`, `deleteNode`, `moveNode`; section roots are refused with `VALIDATION`, sibling positions stay contiguous: gap-close the old siblings, then shift the new ones, then land the row) and returns the row(s); the renderer store merges the returned records with pure, tested helpers (`insertIntoIndex`, `duplicateIntoIndex`, `removeFromIndex`, `moveInIndex`, `planRemoval` for the post-delete selection fallback) instead of reloading; `expandAncestors` opens the path to a new node. The structural rule (what level fits under which parent) has one owner, `canPlaceLevel` in `src/shared/labels.ts`, used by main and by `resolveDropTarget` in `placement.ts`. `tree:move`'s `afterId` is tri-state: `undefined` appends, `null` inserts first, a string inserts after that sibling. Delete confirms through `dialogs.confirm` in `ManuscriptTree.tsx`. Drag and drop is native HTML5 (no dependency); the transient drag state and the indicator live in `ManuscriptTree.tsx`, not the store. In e2e, `locator.dragTo()` on an expanded folder row needs an explicit `sourcePosition` inside the header row, or it grabs the centre of the whole subtree. `placement.ts` is the one place that turns "selection + level" into `{ parentId, afterId }` (bottom bar, context menu, and later Insert menu/shortcuts all use it). `contextMenuItems.ts` returns plain `{ id, label }` data so F-7.1 can render the same items natively; front/end matter rows get the section's template items (`template:<id>`, parsed back with `templateIdOf`, never cast) after the generic pair (F-2.6). `src/shared/matterTemplates.ts` is the one owner of the 14 templates (Tiptap JSON inside the editor schema); `tree:create` takes an optional `template`, main fills title, content, `matterType`, and `wordCount` and refuses a template outside its section; the renderer's `createFromTemplate` selects the new document without inline rename and adds its words to every ancestor rollup. Default titles come from `defaultNodeTitle` in `src/shared/labels.ts`.
- `src/renderer/features/editor/` (F-3.1) — `extensions.ts` is the one owner of the document schema: `buildExtensions({ sceneBreak, onSave })` returns StarterKit trimmed to the spec (no lists, links, code blocks, horizontal rules, or trailing node; the trailing node made a freshly applied heading read inactive after select-all), `TextAlign` on headings and paragraphs, and the custom `SceneBreak` atom block (`<div data-scene-break>` with the text as an extension option, not stored in the node, so restyling applies to old breaks; `insertSceneBreak` opens a paragraph after it). `documentStore.ts` owns the loaded document (`id`, `content`, `dirty`; generation guard) and autosave (F-3.2): `edit(json)` records the latest editor state and restarts a 1 s debounce; `flush()` writes the pending job through `document:save`, waits for any write already on the wire (writes are serialized, so close/quit cannot outrun a save that already left), keeps the job for retry on failure unless a newer edit replaced it, and merges the returned word count into the tree via `useTreeStore.setWordCount` (delta walk up the ancestors, no reload); `saveNow()` is Ctrl+S (the `SaveShortcut` extension, `Mod-s`); `load(id)` flushes the outgoing document without waiting and registers the flusher with the pending-save registry once, `clear()` unregisters. Pending jobs (a map keyed by document id, so a failed save for one document survives edits to another), the timer, and the in-flight promise are module state; tests must call `resetDocumentStore()` in `beforeEach`. `src/shared/wordCount.ts` is the one word counter (main caches it on `node.word_count`).
- Stacked editing (F-3.8, F-2.5): `documentStore.ts` holds every loaded document in `docs: Record<id, { content, dirty }>` with `load(id)`/`unload(id)`/`edit(id, json)`, per-id debounce timers and load tokens, and one serialized write queue (`drain`). `DocumentEditor.tsx` is the region: it owns the load/unload effect, the Tiptap instance, an optional own toolbar, and an `onFocus(editor)` callback; `EditorPane.tsx` is the single-document wrapper. `StackedEditor.tsx` renders `descendantDocuments(index, folderId)` (pure, in `treeStore.ts`) as `<section aria-label={title}>` regions with one shared `Toolbar` targeting the last-focused region (tracked as `{ id, editor }` and dropped when the region leaves the stack); the separator is decided per folder from `sectionOf` (scene-break text for manuscript, `<hr>` for matter). The empty-folder invitation creates through `createLevel`/`createGeneric` with `{ keepSelection: true }` so the stack stays. `App.tsx` `MainPane` renders `StackedEditor` for folders and `EditorPane` for documents. The book-like column (F-3.4) and formatting (F-3.6) have one owner, `column.ts`: `COLUMN` is the utility string every editing surface uses and `editorStyle(settings)` sets the `--ms-editor-*` variables (max width, font size, line height, paragraph spacing, first-line indent; token fallbacks in `tokens.css`, consumed by `.ms-editor` rules in `app.css`) on the pane; this is the one sanctioned inline style in the editor. Settings: `src/main/project/settingsStore.ts` reads/upserts the `editor` row (falls back to `defaultEditorSettings(format)` on a missing or invalid row); `src/renderer/features/editor/settingsStore.ts` is the renderer owner (`load` with the tree on project open, `update(patch)` optimistic with one 150 ms debounced `editorSettings:set`, revert and toast on failure, registered with the pending-save registry, `clear` on close; `useEditorSettings(format)` falls back to the format default; tests call `resetEditorSettingsStore()`). `EditorSettingsTab.tsx` hosts the controls plus a live preview (a static sample styled with `editorStyle`, `.ms-editor.ms-preview` drops the editor's min-height) inside the Settings dialog (F-7.5). Changing the scene-break text rebuilds the editor instance (the text is an extension option); `documentStore.edit()` keeps `docs[id].content` at the latest JSON so the rebuild starts from unsaved typing. The empty state (F-3.5) is the `empty-state` block in `App.tsx`. Word counts (F-3.3): `StatusBar.tsx` is presentational (`status-words`, `status-delta` test ids; formatters in `wordFormat.ts`); `DocumentStatusBar` inside `DocumentEditor.tsx` counts the editor live with `useLiveWordCount` (a `useSyncExternalStore` on Tiptap's `update` event, snapshot cached by document identity so caret moves never recount; saved count while loading), the stack shows the folder's `wordCountRollup` with no delta (folder rollups move with structure); the session delta comes from `sessionBaseline` in the tree store (a copy of the rollup taken in `load()`, cleared in `clear()`; `sessionDelta(state, id)`), so nodes created this session count as all new. `Toolbar.tsx` snapshots its `editor` prop inside `useEditorState`'s selector because Tiptap 3 does not refresh the selector when the editor prop changes. `EditorPane.tsx` loads by id and mounts a fresh editor instance per document, keyed by id and load state and constructed with the content, so loading never enters the undo history and undo cannot cross documents; while loading the editor is read-only and the toolbar gets `editor={null}`. `Toolbar.tsx` reads active state through `useEditorState` and exposes it as `aria-pressed`. `src/shared/tiptap.ts` holds the recursive zod `TiptapNode` schema and `EMPTY_DOC` for main, renderer, and later importers. jsdom lacks what ProseMirror needs to mount, so `src/renderer/test/setup.ts` polyfills `Range.getClientRects`/`getBoundingClientRect` and `document.elementFromPoint` once for every renderer test.
