## 2026-10-13 · F-16.22 · P2b slice 3 review: calls made while tightening the live knows run
- Question: The review of slice 3 found that the live knows run could pass with a wrong "suspects" or "believes otherwise" line on the wrong person, or with an invented "told by"; that one provider error (a 429, or the credit running out) lost the whole report; that a model with no price and no reported cost made the 50¢ stop blind; and that an `OPENAI_BASE_URL` in your shell could quietly move the OpenAI route. Fixing them needed these calls (nothing changes in the app, nothing in v1).
- Chosen (decided by Claude, unconfirmed):
  1. **Attribution precision counts every line the grid shows as a cell**: counted lines and partial ones (suspects, believes otherwise), each judged against a label in its scene (learner, secret, how class), and a line that names a source ("told by Mrs. Pocock") is right only when its label names that source. The report lists counted lines no label has, partial lines no label has, and lines with a source no label names, each under its own heading. The negatives (a dream, town talk, Mr. Harrow) are checked over the same cells, so "Mr. Harrow believes otherwise about the debts" fails the run as surely as a counted line would. This tightens P2b-D23's attribution bar (still 90 %).
  2. **A provider error stops that pass, not the report**: the scene it happened on and the code (rate limit, no credit, provider down) are recorded, the pass is marked failed ("stopped by a provider error after N scenes"), and the report is written with what was read and what it cost; the second pass still starts (a 402 or a bad key fails at once and costs nothing). The planted-error run does the same, through its spot checks too. No automatic retry.
  3. **A cost the 50¢ stop cannot see stops the run**: an answer with no reported cost on a model the price tables do not list (a `MYTHSCRIBE_EVAL_*_MODEL` override, or another server) counts 0 USD, so the run stops there and says "cost unknown for <model>"; a server on this machine (`OPENAI_BASE_URL` on localhost) charges nothing and is never stopped for it.
  4. **The OpenAI route goes to OpenAI**: with only `OPENAI_API_KEY` set, the run's requests go to `api.openai.com` even if your shell exports `OPENAI_BASE_URL` (the OpenAI library would otherwise read it on its own); the app's own path is unchanged (the e2e test relies on it).
  5. **The adversarial replay now does what the plan asked**: the dream in h06 and the town's talk in h07 are also offered as Lise being told of the engagement (already listed by then); the checker answers "only in a dream" and "only as rumour", and both lines are kept with that mode and voice, never counted, shown apart from her cell (which stays her overhearing in h05). The new-secret plants stay too.
  6. **The live fidelity run sends every case once**: each case's cache key now covers its temperature and output cap, so no two cases can share an answer, and the offline test checks one request per case at the reported cost.
- Alternatives: a separate partial-precision bar; ignoring sources in attribution; retrying a 429 once after a pause; a conservative per-token estimate instead of stopping on an unknown cost; clearing `OPENAI_BASE_URL` only in the tests; recording the plan departure instead of adding the plants.

## 2026-10-12 · F-16.22, F-16.23 · P2b slice 1 (who-knows-what data, threads, years and ages; no AI, nothing to see yet): calls made while building it
