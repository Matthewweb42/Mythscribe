# MythScribe architecture (as built)

The per-area notes that used to live in `CLAUDE.md`. Read the bullet for the area you are about to touch; do not read the whole file. Update the bullet in the same change when the code changes (the same rule as `FEATURES.md`).

## Areas

- `src/shared/ipc/contract.ts` — the IPC contract: every channel's zod input/output, main→renderer events, error codes. Add a channel here first; both sides are typed from it.
- `src/main/ipc/registry.ts` — `register(channel, fn)` validates input and wraps errors; throw `AppError(code, message)` from handlers. `emit(windows, event, payload)` pushes events. Handlers live in `src/main/ipc/handlers.ts`.
- `src/main/db/` — `schema.ts` (Drizzle), `migrations/` (generated SQL, numbered, committed, never edited), `migrate.ts` (runner with `schema_migrations` table), `connection.ts` (`openDatabase` applies pragmas and migrations).
- `src/main/project/` — `projectStore.ts` creates/opens the `<Name>.mythscribe/` folder; `manager.ts` owns the single open project and notifies on change.
- `src/main/project/seed.ts` — pure `seedSkeleton(format)` (3 sections + Part/Chapter/Scene skeleton, 17 rows) and `seedSettings(format)`; run inside `createProject`'s transaction. `src/main/tree/treeStore.ts` — `insertNodes`, `listNodes` (ordered parent, position, id; roots first), `toTreeNode`; `TreeDb` accepts the orm or a transaction handle.
- `src/shared/labels.ts` — `SectionType`/`HierarchyLevel`/`NodeKind` enums (one owner; Drizzle columns use the same tuples), `sectionLabel(format, section)`, `levelLabel(format, level)`, `skeletonSummary(format)`. Section rows store the canonical key (`front`/`manuscript`/`end`) as `title`; the UI must label roots via `sectionLabel`, never `title`.
- `src/shared/editorSettings.ts` — zod `EditorSettings` and `defaultEditorSettings(format)` (F-3.6 defaults); stored in the project `settings` table under key `editor` as JSON.
- `src/main/appState/` — app-level (not per-project) state in `<userData>/app-state.json`: `appStateStore.ts` reads lazily, validates with zod, writes atomically; `recents.ts` holds the pure recents list operations. Recents are recorded on the `manager.onChange` hook in `handlers.ts`. F-7.9 window state belongs in the same file. `MYTHSCRIBE_USER_DATA` overrides the userData directory (used by e2e for isolation; the single-instance lock also lives there, so e2e and `npm run dev` can run concurrently).
- Autosave (F-3.2, F-3.7): `src/renderer/features/editor/autosaveStore.ts` is the one owner of the machinery: `createAutosaveStore<T, R>({ empty, get, save, onSaved?, delayMs? })` returns `{ useStore, reset }` with `docs[id] = { content, dirty }`, `load/unload/edit/flush/saveNow/clear`, per-id debounce timers and load tokens, pending jobs keyed per id, one serialized write queue, retry after failure unless a newer edit replaced the job, and its own pending-save registration (first load) and unregistration (clear/reset). `documentStore.ts` (`useDocumentStore`, `resetDocumentStore`, `onSaved` merges the word count into the tree) and `notesStore.ts` (`useNotesStore`, `resetNotesStore`) are its two instances. Notes: `src/main/document/notesStore.ts` (documents and folders; section roots refused by `parentId === null`; shares `parseStoredTiptap` with the document store); `NotesEditor.tsx` takes only `id`; `NotesPanel.tsx` (toggle button in both toolbars' `right` slot, resizable handle with `role="separator"`, width clamped in-file); its open state and width live in the layout store (F-7.2); `App.tsx` `MainPane` renders it beside the editor for documents and folders.
- Sidebar tabs (F-7.3 shell): `src/shared/sidebarTabs.ts` holds the zod `SidebarTabId` enum (all seven ids, schema-stable; `Layout.sidebar.tab` persists the active one); `src/renderer/features/shell/sidebarTabs.ts` is the static registry (`SIDEBAR_TABS`, Manuscript only until later features append their entry) and `SidebarTabs.tsx` the ARIA tab bar + tabpanel; `ManuscriptTab.tsx` composes the tree and the create bar. A persisted id with no registered tab falls back to the first tab at render. `Layout` requires the tab (so the IPC input and output types match); `StoredLayout` in `src/shared/layout.ts` is the lenient reader the app-state file uses, defaulting a pre-F-7.3 file to Manuscript.
- Tags (F-4.1): `src/shared/tags.ts` is the one owner of the seven `TAG_CATEGORIES` (camelCase keys), `TAG_CATEGORY_LABEL`, `DEFAULT_CATEGORY_COLOR`, `HEX_COLOR`, `TAG_NAME_MAX`, and `toTagName` (kebab-case; letters and digits of any script are kept, so "Zoë" stays "zoë"). Schema: `tag` (name unique after normalization; `parent_id` self-reference, `ON DELETE SET NULL`) and `document_tag` (node↔tag link, unique pair, cascades from both sides; empty until F-4.4/F-4.6 write it) in migration `0002_tags`. `src/main/tag/tagStore.ts` mirrors the tree store: `listTags`, `getTagWithUsage`, `createTag`, `updateTag` (partial patch; cycle check walks `parentId` up), `deleteTag`; `usageCount` is derived with a `COUNT` join, never stored. Channels `tag:list`/`tag:create`/`tag:update`/`tag:delete`; errors `VALIDATION` (empty after normalization, self/descendant parent), `ALREADY_EXISTS` (name collision), `NOT_FOUND`. `migrate.test.ts` hard-codes the bundled migration count, so every new migration bumps it.
- Tag Manager (F-4.2): `src/renderer/features/tags/tagStore.ts` is the renderer owner of the bank (`byId`/`ids` ordered by name then id like `tag:list`; generation-guarded `load` on project open and `clear` on close from `App.tsx`, the tag load never blocks the tree; `create`/`update`/`remove` await main and merge the returned row, never re-list; `resetTagStore()` in tests). A tag created through the raw bridge (e2e) is invisible to the store until the next load. `TagsTab.tsx` composes the category strip (ARIA tablist over `CATEGORY_FILTERS` from `categoryFilter.ts`, where `'all'` is a UI-only filter and `defaultCategoryFor('all')` is `custom`), the search, `TagList.tsx` (`role="list"` of button rows; the color dot is the one inline style), `TagForm.tsx` (keyed on the filter so category and color re-default; a hand-picked color survives a category change), and `TagDetail.tsx` (labels stacked above controls so the sidebar minimum never overflows; inline rename keyed on the name so the field re-syncs to the kebab-cased result; color drag steps coalesce to one write in flight plus the latest pick; delete via `dialogs.confirm` danger). Filter, query, and selection are component state. No nesting UI (`parentId` is never sent). The create form's bottom row wraps so the sidebar minimum (15 %) never overflows; check new sidebar content at that width in a 1024 px window (tabpanel `scrollWidth` vs `clientWidth`; the resize handle deliberately straddles the border, so measure the panel, not the `aside`).
- Tag templates (F-4.3): `src/shared/tagTemplates.ts` is the one catalogue (`TAG_TEMPLATE_IDS`, `TAG_TEMPLATES`: Standard Fiction, Mystery, Fantasy, Sci-Fi, each 4–8 kebab-case tags per non-custom category, colors always the category default). `loadTagTemplate` in the main tag store is one transaction that reuses `insertTag`, skips by normalized name across the whole bank, and returns `{ created, skipped }` in template order through `tag:loadTemplate`. The renderer store's `loadTemplate` merges `created` in one `set`; `TemplateLoader.tsx` (select + Load, above the search in the list view only) confirms via `dialogs.confirm` and toasts the counts.
- Document tag bar (F-4.4): `src/main/tag/documentTagStore.ts` (`listDocumentTags`, `addDocumentTag`, `removeDocumentTag`; idempotent, transactional, documents only via the node row's `kind`, return the tag with its fresh `usageCount`) behind `documentTag:list`/`add`/`remove`. Renderer: `src/renderer/features/tags/documentTagStore.ts` owns `tagIdsByNode` (per-node load tokens, cleared on project close); `add`/`remove` merge the returned tag into the bank (`useTagStore.merge`, re-sorts only on a name change) before splicing the ids, so the Tags tab's counts move without a reload and chips always render the bank's record (rename/recolor shows at once). `TagBar.tsx` (`role="region"` "Tags", collapse toggle, chips with `Remove <name>`, bottom `ResizeHandle`) and `TagPicker.tsx` (searchbox + listbox of unassigned tags, ArrowUp/Down, Enter links, Escape/outside click closes, closes after one pick) mount only in the single-document view (`DocumentEditor` with its own toolbar), never in stacked regions. `Layout.tagBar = { open, height }`: height in px, zod floor `TAG_BAR_MIN_HEIGHT` (100), the 60 vh ceiling clamped by `clampTagBarHeight` at drag time and `max-h-[60vh]` at render; `StoredLayout` defaults it for old app-state files; `layoutStore` has `toggleTagBar`/`setTagBarHeight`/`resizeTagBarBy`. `ResizeHandle` supports `top`/`bottom` (horizontal, `aria-orientation`). The editor surface (`.ms-editor`) is a flex item that fills its scroll container (no viewport-relative min-height), so chrome above it never forces a scrollbar; stacked regions keep their own `6em` floor.
- Scene metadata (F-4.5): `src/shared/sceneMeta.ts` (zod `SceneMeta` `{ location, pov, timeline }`, `EMPTY_SCENE_META`, lenient `parseStoredSceneMeta`) stored as JSON in the existing `node.scene_meta` column, no migration. `src/main/tree/contentTarget.ts` `requireContentTarget(db, id, what)` is the one "any node but a section root" rule shared by notes, scene metadata, and document tags (so chapters and parts carry tags and metadata too). `src/main/document/sceneMetaStore.ts` behind `sceneMeta:get`/`sceneMeta:set`. Renderer: `sceneMetaStore.ts` is the third `createAutosaveStore` instance (debounce, flush, pending-save registration for free); `MetadataPane.tsx` (`role="group"` "Scene metadata") loads per node on mount and unloads on unmount, fields disabled until the load lands; `SuggestInput.tsx` is the combobox (label + input `role="combobox"`, listbox of names starting with the text, ArrowUp/Down, Enter fills, Escape/blur close; free text allowed) fed by the bank's setting tags (Location) and character tags (POV). `TagBar.tsx` shows the pane only for a node with a hierarchy level, behind `layout.tagBar.split` (fraction 0.3–0.7, `TAG_BAR_SPLIT_LIMITS`, default 0.4, its own `.default` inside `StoredLayout`'s tagBar schema so a `{ open, height }` file still loads; the drag is measured against the pane row's width via `resizeTagBarSplitBy`). `StackedEditor` mounts the bar once at the top for the folder itself (also for an empty folder). Tests that enumerate stacked document regions filter `getAllByRole('region')` to `<section>` elements, and the e2e uses `section[aria-label]`, because the bar is a region too.
- Scene brief (F-14.3), main side: `src/shared/sceneMeta.ts` adds `SceneBrief` `{ goal, conflict, turn, beat, after }` (each ≤ `SCENE_BRIEF_FIELD_MAX` 200) as `SceneMeta.brief`, zod-defaulted so a row stored before F-14.3 still parses (no migration), plus `SCENE_BRIEF_FIELDS`, `EMPTY_SCENE_BRIEF`, `emptySceneMeta()`, `isBriefEmpty`, `renderSceneBriefBlock({ current, previous, next })` — the one prompt block every feature carries: the scene's non-empty lines, then the previous scene's `after` (else its `turn`) and the next scene's `goal` — and `BRIEF_SCENE_CHAR_BUDGET` 20,000 / `BRIEF_TEXT_MIN` 200. `src/main/document/sceneNeighbours.ts` `sceneBriefBlock(db, nodeId)` and `sceneNeighbours` read it over `manuscriptDocuments` (F-14.3 made it reading order: sorted by each row's chain of positions from the root, because `listNodes` groups by parent id, which is not reading order across chapters; the provenance and consistency reports gained the same order); a node that is not a manuscript document gets its own brief and no neighbours. Feature id `brief` (tier `fast`, JSON, `minDial` 1, budgets 200 out / 6,000 in); `FEATURE_INPUT_BUDGETS.ghostText` rose 1,500 → 2,000 to carry the block. Contract `ai:draftBrief { nodeId, requestId }` → `AiDraftBriefResult`. Main: `src/main/ai/prompts/brief.v1.ts` (`BRIEF_RULES` opens with `You are the scene-brief feature inside a novel-writing app.`, which the e2e fake server keys on; system = rules + the `Scene:` line, user = the scene text + `Draft the brief.`; no voice block), `src/main/ai/draftBrief.ts` `draftBrief` (dial gate first, the `BRIEF_TEXT_MIN` text gate, head cut to `BRIEF_SCENE_CHAR_BUDGET` → `truncated`, `fast` + `json`, hash over the scene text as sent and the metadata; `parseBriefAnswer` is lenient field by field — a missing or non-string line reads as '' — and PROVIDER when the answer is not a JSON object), handler `ai:draftBrief` (one pending `ai_proposal` row holding the brief as JSON; nothing is written to the node, the pane's Use draft writes the fields through `sceneMeta:set`). The block rides in `ghostText.v2`/`ghostTextRegen.v2`, `chat.v2`/`chatRegen.v2` (Agent mode), and `critique.v2`/`critiqueRegen.v2`; `rewrite.v1` is deliberately not wired, since a rewrite must keep the passage's meaning.
- Scene brief, renderer (F-14.3): `MetadataPane.tsx` grows a **Brief** disclosure (collapsed by default, `aria-expanded`/`aria-controls`) over the five `SCENE_BRIEF_FIELDS` inputs, each editing `meta.brief` through the same `sceneMetaStore.edit`, so the brief autosaves and flushes with the other three fields. The pane scrolls (`h-full overflow-y-auto`) because five more lines outgrow the bar; opening the brief grows the tag bar to `TAG_BAR_BRIEF_HEIGHT` (300 px) when it is shorter and never shrinks it, and the default tag-bar height rose 120 → 180 px so the three rows plus the Brief row fit collapsed with no scrollbar (`SuggestInput`'s listbox is fixed-positioned and re-measured on typing, scroll, and resize, because an `overflow-y: auto` ancestor clips an absolutely positioned list). `briefDraft.ts` (`useBriefDraft`) owns the Draft-with-AI flow for a document: the gate is the tag bar's (dial + toggle via `AI_DATA_SHARING.brief`, `BRIEF_TEXT_MIN` characters of live text from `useDocumentStore`, nothing in flight; the reason shows in the button's `title`), the request flushes the document store first and goes through `useAiActivityStore().track('brief', …)` so Cancel (F-5.10) and the header indicator find it, and the answer is a proposal (F-14.5) settled accepted on **Use draft** (which fills all five fields) or rejected on **Discard**; a `CANCELLED` reply returns to idle in silence. `BriefDraftPanel.tsx` renders the three states (pending + Cancel, failure + next step, the `role="group" "Brief draft"` list with `model · formatRequestCost · cached`). The e2e drafts a brief on Scene 1 before the VibeWrite step (fake server keys on `BRIEF_SENTINEL`) and then asserts the ghost-text and critique bodies carry the brief block.
- Inline tags (F-4.6): `@tiptap/suggestion` (pinned to the core version) is the only addition. `src/renderer/features/editor/InlineTag.ts` owns the `inlineTag` inline atom (attrs `{ id, name }`, `marks: ''`, not draggable; `renderHTML` emits `<span data-inline-tag data-id data-name class="inline-tag">#name</span>` with `--tag-color` from the bank; `parseHTML` keeps copy/paste), `suggestItems(query)` (substring match plus a "Create #kebab" row unless an exact name exists), the `#` Suggestion plugin (inserts the node plus exactly one plain space, swallowing a following space, then `documentTagStore.add`), and `resyncInlineTags(view, byId)` (a DOM-only repaint on bank changes: no transaction, no dirty flag). `InlineTagSuggestList.tsx` is the `role="listbox"` popup mounted by the plugin's own floating-ui `mount` helper (follows scrolling, closes on outside click; Escape is the plugin's): ArrowUp/Down wrap, Tab and Enter pick, the highlight returns to the first row whenever the rows change (a stale index from a long list once clamped to "Create"), and a row is highlighted by pointer movement, not by appearing under a resting pointer. `buildExtensions({ inlineTagNodeId })`: only manuscript documents pass it, so notes never get the node. `src/shared/inlineTags.ts` `countInlineTags(doc)` feeds the tag bar's "Inline tags" list (documents only) and `wordCount` counts a token as one word. Right-click on a token opens the manuscript `ContextMenu` with Remove (node only; the link stays) and Open in Tag Manager (opens the sidebar, `setSidebarTab('tags')`, `useTagStore.requestSelection(id)`, which `TagsTab` consumes once and clears). Known gaps: Ctrl+Z after an insertion leaves the link; a token pasted into another document is counted there but not linked; Edit on the token menu is deferred.
- AI provider and keys (F-5.1): `src/shared/ai.ts` is the one owner of `AiProviderId`, `Tier`, `DEFAULT_MODELS` (`fast: gpt-5.4-mini`, `strong: gpt-5.4`; F-5.11 turns it into a setting), `maskKey`, the `AiErrorCode` taxonomy (`NO_KEY | INVALID_KEY | RATE_LIMIT | QUOTA | NETWORK | PROVIDER`), `AI_NEXT_STEP` copy, and the `AiStatus`/`AiTestConnectionResult` shapes. `src/main/ai/providers/types.ts` is the generic `Provider` interface (`complete`, `stream`, `testConnection`, results carry `usage`) plus the `AiProviderError` class per code (SDK error on `cause`, fixed copy in messages, never the key); `openai.ts` is the only file importing `openai` (`buildOpenAiProvider(key, { fetch? })`, Chat Completions with `max_completion_tokens` and JSON mode, `maxRetries: 0`, `testConnection` = `models.retrieve` on the fast model, `mapOpenAiError`: 401 → INVALID_KEY, 429 + `insufficient_quota` → QUOTA, other 429 → RATE_LIMIT, connection → NETWORK, else PROVIDER with the status). `src/main/ai/keyStore.ts` (`AiKeyStore`) keeps `<userData>/ai-keys.json` `{ version, keys: { openai: <base64 ciphertext> } }` via `safeStorage` (atomic write, lenient read; a corrupt file reads as no key); `encryption()` is `os | plain | none`. `src/main/index.ts` calls `safeStorage.setUsePlainTextEncryption(true)` on Linux so a keyring-less box (this WSL machine) stores the key obfuscated and the AI tab warns; Windows/macOS use the OS store. `src/main/ai/registry.ts` (`AiProviderRegistry.get()`) rebuilds the client only when the decrypted key changes. Channels `ai:getStatus` (`hasKey`, masked `hint`, `encryption`), `ai:setKey`, `ai:clearKey`, `ai:testConnection` (expected failures come back as data with `code` and `nextStep`; only unexpected errors throw). The plaintext key exists only in main. Renderer: `src/renderer/features/ai/aiStore.ts` (`load/setKey/clearKey/test`, `resetAiStore()`) and `AiSettingsTab.tsx`, registered as the AI tab in `SETTINGS_DIALOG_TABS`. The e2e runs a fake OpenAI on `127.0.0.1` through the SDK's `OPENAI_BASE_URL` (it echoes the requested model id); no test may reach api.openai.com. Tiers (F-5.11): the mapping is the app-state field `models` (`AiModels`, enum-keyed per provider, defaulted from `defaultAiModels()` so old files load; `TIER_USE` holds the per-tier hint copy, all in `src/shared/ai.ts`); the registry hands the cached provider a live `resolveModel(tier)` closure over `appState.get().models`, so `ai:setModels` applies on the next request without a rebuild; `AiStatus.models` carries the effective map; the AI tab's Models group commits on blur/Enter (blank or unchanged writes nothing, a refused save reverts and toasts) and its Reset is disabled at the defaults. Feature code names a tier, never a model; `grep gpt-` should hit only `src/shared/ai.ts` and tests.
- AI request path (F-5.14): every AI feature calls `runAiRequest(deps, input)` in `src/main/ai/request.ts` (pure over injected deps; `buildAiRequestDeps` binds the open project's db, the registry, and app state). Order: clamp `maxTokens` to `FEATURE_BUDGETS[feature]`, refuse an input estimate over `FEATURE_INPUT_BUDGETS` with `BUDGET`, refuse when the day's tally would exceed the cap (a cap of 0 pauses AI, cached answers included), cache lookup by `cacheKey` (feature, prompt version, model, json mode, context hash, messages), provider call, `priceFor(model)` (unknown → cost 0, `priced: false`; `MODEL_PRICING` in `src/shared/ai.ts` is the one owner), ledger row, cache write with the 500-row eviction, tally update. A provider error is neither logged nor cached; a cache hit logs a zero-cost row with `cached = true`. Tables `ai_usage` and `ai_cache` (migration `0003_ai_usage`) in the project db via `usageStore.ts` and `cacheStore.ts`; the daily cap and today's tally (`AiUsageState`, local-day rollover in `dailyCap.ts`) live in app state so the cap holds across projects. `AiFeature` (`ghostText | tags | summary`; extend it when a feature lands), `estimateTokens` (chars/4), `DAILY_CAP_*`, and `AiUsageSummary` are in `src/shared/ai.ts`; `src/shared/aiThrottle.ts` `shouldTrigger` is the ghost-text trigger discipline for F-5.3. Channels `ai:usageSummary` (`today` is app-wide, `total`/`byFeature` are this project's; the AI tab's Usage block says so) and `ai:setDailyCap`. The F-14.4 dial gate belongs to each caller, not to `runAiRequest`.
- Prompt versions and the eval harness (F-5.12): `src/main/ai/prompts/catalogue.ts` lists every shipped `<feature>.v<N>.ts` (`PROMPT_VERSIONS`, `PromptVersion`, `PROMPT_CATALOGUE` → feature, tier, `json | text`, the shipping feature); `runAiRequest` takes a `PromptVersion`, not a string, so a feature cannot send an uncatalogued prompt. A new prompt is a new file exporting `<NAME>_PROMPT_VERSION` equal to its basename, a golden test, a catalogue line, and at least one case in `src/main/ai/eval/fixtures.ts`; `catalogue.test.ts` and `prompts.eval.ts` refuse anything missing. Shipped versions are never edited (their goldens and their rows in `src/main/ai/eval/token-report.md` pin them). The eval project (`vitest.config.ts`, `*.eval.ts` under `src/main/ai/eval/`, `npm run eval:ai`) is offline by default and pins the token report with `toMatchFileSnapshot` (`-u` to accept; the diff is the token delta); the live block (`MYTHSCRIBE_EVAL_LIVE=1`, `OPENAI_API_KEY`, optional `OPENAI_BASE_URL`) calls `buildOpenAiProvider` directly, scores prose with `postProcessGhostText` + `checkGhostTextFidelity` and JSON against the bank, and writes `test-results/eval-ai/live-report.md`. The fixture's maxed ghost-text case sits at 1 432 of the 1 500-token budget (68 headroom; the regenerate at 1 459): a voice block at its 600-token budget plus the author block at its 130 (F-14.2), a full caret window, notes, and long metadata; anything added to `ghostText.v2` must come out of that.
- AI dial (F-14.4): `src/shared/aiSettings.ts` owns `AiDial` (0 Off, 1 Ask, 2 Suggest, 3 Draft; `AI_DIAL_LABEL`/`AI_DIAL_MEANING`), `AiSettings` `{ dial, features }` with `defaultAiSettings()` (dial 0, all toggles on), `AI_DATA_SHARING` (the one registry per `AiFeatureId`: label, what is sent, minimum dial; the panel renders it and `isFeatureAllowed` reads it; every feature must have an entry, a test enforces it), and `isFeatureAllowed(settings, feature)` (monotonic: level ≥ the feature's minimum and the toggle on). `AiFeatureId` in `src/shared/ai.ts` is the superset owner (`ghostText`, `tags`, `summary`, `chat`, `authorMode`, `query`, `critique`, `embeddings`); `FEATURE_BUDGETS`/`FEATURE_INPUT_BUDGETS` are partial with `outputBudget()`/`inputBudget()` defaults. Per project under key `ai` in the `settings` table (`getAiSettings`/`setAiSettings` beside the editor ones; fallback to defaults, no seeding) behind `aiSettings:get`/`aiSettings:set`. `src/main/ai/dial.ts` `assertFeatureAllowed` throws `AiDisabledError` (code `DISABLED`, next step names Settings); every caller checks it before `runAiRequest`, which stays gate-free. Renderer: `aiSettingsStore.ts` (editor-settings pattern: optimistic, one debounced write, revert and toast, pending-save registration, loaded with the tree, cleared on close, `resetAiSettingsStore()` in before and after each) and `AiDialSection.tsx` ("This project" at the top of the AI tab: radiogroup with roving tabindex, toggles disabled below level with "(needs X)" in the label, the data-sharing table, and the closing note).
- Tag recommendations (F-4.7): the template for every AI feature. `src/main/ai/prompts/tags.v1.ts` is the first prompt (system rules first, then the bank names, then the passage last; JSON `{ "tags": [...] }`; `TAGS_TEXT_CHAR_BUDGET` 6 000 chars head-truncated; `maxTokens` from `outputBudget('tags')`) with a golden snapshot test and a budget assertion; new prompt versions are new files. `src/main/ai/recommendTags.ts` is the use case: `getDocumentContent` (documents only) → `docToText` (`src/shared/docText.ts`, the one plain-text extractor; inline tags render as `#name`) → the 50-char gate (`TAGS_MIN_CHARS`) → `assertFeatureAllowed(settings, 'tags')` → `runAiRequest` (`tags`, `fast`, `json`, `promptVersion`, `contextHash` over text plus sorted bank names) → strict zod parse → `toTagName` on both sides, unknown, linked, and duplicate names dropped, cap 8. `ai:recommendTags { nodeId }` returns `AiRecommendTagsResult`: success with the tags, usage, cost, model, cached; expected failures as data via `aiFailure` (code, message, next step) like `ai:testConnection`. Known limitation: a malformed answer is cached inside `runAiRequest` before the parse; a validation hook on the request path is a later change. The tag bar's Recommend button flushes the document store first (main reads the saved row), is disabled under 50 characters, keeps its state per node id in component state, links accepted chips through `documentTagStore.add` (nothing enters the manuscript), and shows `model · cost · cached` from `formatRequestCost`. The e2e fake server answers `POST /v1/chat/completions` with canned tag names.
- Writing presets (F-5.2): `src/shared/presets.ts` owns `PRESET_IDS` (general, action, suspense, dialogue, romance, worldBuilding, custom), `PresetParams` (temperature 0–1.5, `maxSuggestionTokens` 20–60 so the ghost-text budget is never exceeded, `styleInstruction` ≤ 300 chars, `allowNewElements`), the six built-in `PRESETS` with one-sentence instructions, `WritingPresets` `{ active, custom }`, `defaultWritingPresets()`, and `resolvePreset(settings)` (the params the prompt builders consume; they append the instruction after the voice profile, never in place of it). Per project under key `presets` in the settings table (`getWritingPresets`/`setWritingPresets`, fallback to defaults) behind `presets:get`/`presets:set`. ## Known gotchas

- The e2e "flake" (2026-09-11/12: the wizard's name field gaining stray letters such as `Smoke Novelo`, `Smoke NovelaR`, `Smoke Novelul`, or shrinking after Back) was keyboard focus, not load: on WSLg the shown Electron window steals the desktop focus, so anything typed on the machine while the test runs lands in the test's inputs. Since 2026-09-12 main calls `win.showInactive()` when `NODE_ENV === 'test'` (the harness sets it), and the test passed back to back afterwards. If the wizard step ever fails again, keep `test-results/**/trace.zip`, check the recorded value for foreign characters, and do not add Playwright retries to hide it. `pgrep -f electron` matches the calling shell's own command line, so check `/proc/<pid>/cmdline` before concluding an instance is stale.
- Electron cannot open an X11 window on the dev machine (2026-09-17, during F-5.7): every launch, `npm run test:e2e`, `npm run dev`, and a three-line BrowserWindow app alike, dies with SIGTRAP right after the zygotes start, while `electron --version` works, `xset q` answers, and the `/tmp/.X11-unix/X0` and WSLg Wayland sockets exist. `--ozone-platform=wayland` keeps the process alive and Playwright reaches the DOM, but nothing paints, so every click times out on "visible, enabled and stable"; `ELECTRON_OZONE_PLATFORM_HINT=wayland`, `--disable-gpu`, and `--ozone-platform=x11` do not help. It is the WSLg session, not the repo (no dependency changed since the last green e2e on 2026-09-15). Fix: `wsl --shutdown` from Windows and reopen the terminal, then rerun the e2e. Do not add machine-specific launch switches to the spec.
- Test hygiene (2026-09-12): stores with a debounced write (editor settings, layout, the autosave instances) must be reset in `afterEach` as well as `beforeEach`, because a timer scheduled by a file's last test otherwise fires into the next file's IPC fake (reused workers, no per-file isolation) and shows up there as a stray toast such as `unexpected editorSettings:set`. Four files were missing it; if a similar stray toast appears, look for the file that scheduled the write, not the file that failed.
- The e2e ghost-text step (2026-09-15, seen twice on F-14.3): `editor.click()` lands the caret mid-paragraph and a bare `End` then goes to the end of the soft-wrapped visual line, so typed text and the ghost request land inside the paragraph and the second suggestion never shows. Use `Control+End` (the document end) before typing at the end of the scene; the F-14.7 and F-5.3 steps do now.
- Dev-machine note: projects created before F-1.3 (2026-09-10, e.g. `~/test.sqlite.mythscribe`) have no seeded sections, so `tree:list` returns nothing for them. They are throwaway; delete them rather than adding a repair path. F-2.1 must still render sanely for an empty tree.
