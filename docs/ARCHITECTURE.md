# MythScribe architecture (as built)

The per-area notes that used to live in `CLAUDE.md`. Read the bullet for the area you are about to touch; do not read the whole file. Update the bullet in the same change when the code changes (the same rule as `FEATURES.md`).

## Areas

- `src/shared/ipc/contract.ts` — the IPC contract: every channel's zod input/output, main→renderer events, error codes. Add a channel here first; both sides are typed from it.
- `src/main/ipc/registry.ts` — `register(channel, fn)` validates input and wraps errors; throw `AppError(code, message)` from handlers. `emit(windows, event, payload)` pushes events. Handlers live in `src/main/ipc/handlers.ts`.
- `src/main/db/` — `schema.ts` (Drizzle), `migrations/` (generated SQL, numbered, committed, never edited), `migrate.ts` (runner with `schema_migrations` table), `connection.ts` (`openDatabase` applies pragmas and migrations; `locking_mode = EXCLUSIVE` before WAL, so the WAL index lives in memory and no `-shm` file exists, which fixed "disk I/O error" on Google Drive's H: drive; a second connection to an open project fails with SQLITE_BUSY, so `ProjectManager.closeIfOpen` runs before `project:open` locates a path). Open marker: `src/main/project/openLock.ts` (`OpenLock.acquire` in `createProject`/`openProject`, released by `ProjectSession.close`; refuses with IO naming the other machine).
- `src/main/project/` — `projectStore.ts` creates/opens the `<Name>.mythscribe/` folder; `manager.ts` owns the single open project and notifies on change.
- `src/main/project/seed.ts` — pure `seedSkeleton(format)` (3 sections + Part/Chapter/Scene skeleton, 17 rows) and `seedSettings(format)`; run inside `createProject`'s transaction. `src/main/tree/treeStore.ts` — `insertNodes`, `listNodes` (ordered parent, position, id; roots first), `toTreeNode`; `TreeDb` accepts the orm or a transaction handle.
- `src/shared/labels.ts` — `SectionType`/`HierarchyLevel`/`NodeKind` enums (one owner; Drizzle columns use the same tuples), `sectionLabel(format, section)`, `levelLabel(format, level)`, `skeletonSummary(format)`. Section rows store the canonical key (`front`/`manuscript`/`end`) as `title`; the UI must label roots via `sectionLabel`, never `title`.
- `src/shared/editorSettings.ts` — zod `EditorSettings` and `defaultEditorSettings(format)` (F-3.6 defaults); stored in the project `settings` table under key `editor` as JSON.
- `src/main/appState/` — app-level (not per-project) state in `<userData>/app-state.json`: `appStateStore.ts` reads lazily, validates with zod, writes atomically; `recents.ts` holds the pure recents list operations. Recents are recorded on the `manager.onChange` hook in `handlers.ts`. F-7.9 window state is its `window` key (`WindowState` in `src/shared/windowState.ts`, main-only except `startup:get`/`startup:setReopenLastProject` for the Appearance tab's toggle): the bounds are written on the window's `close` (normal bounds + maximized; fullscreen is never restored) and put back only when `restorableBounds` finds them on a live display; `lastProject` is set on the same `onChange` hook as recents and cleared only by `project:close` (a window close or quit keeps it); `index.ts` opens it after `registerHandlers` and before the window, so the renderer's `project:current` finds it. The e2e's last step relaunches the app on the same userData to check both. `MYTHSCRIBE_USER_DATA` overrides the userData directory (used by e2e for isolation; the single-instance lock also lives there, so e2e and `npm run dev` can run concurrently).
- Autosave (F-3.2, F-3.7): `src/renderer/features/editor/autosaveStore.ts` is the one owner of the machinery: `createAutosaveStore<T, R>({ empty, get, save, onSaved?, delayMs? })` returns `{ useStore, reset }` with `docs[id] = { content, dirty }`, `load/unload/edit/flush/saveNow/clear` (since F-11.1 `load`/`unload` are holder-counted: a second view of the same id shares the first read, and the record is forgotten, its pending edit written, only when the last holder unloads; `reload` re-reads without adding a holder), per-id debounce timers and load tokens, pending jobs keyed per id, one serialized write queue, retry after failure unless a newer edit replaced the job, and its own pending-save registration (first load) and unregistration (clear/reset). `documentStore.ts` (`useDocumentStore`, `resetDocumentStore`, `onSaved` merges the word count into the tree) and `notesStore.ts` (`useNotesStore`, `resetNotesStore`) are its two instances. Notes: `src/main/document/notesStore.ts` (documents and folders; section roots refused by `parentId === null`; shares `parseStoredTiptap` with the document store); `NotesEditor.tsx` takes only `id`; `NotesPanel.tsx` (toggle button in both toolbars' `right` slot, resizable handle with `role="separator"`, width clamped in-file); its open state and width live in the layout store (F-7.2); `App.tsx` `ProjectScreen` renders it as a column for the selected node (a hint while none or an entity page); since 2026-10-06 the column holds the synopsis box, the notes, and the collapsed Scene details (`NotesContent`).
- Sidebar tabs (F-7.3 shell): `src/shared/sidebarTabs.ts` holds the zod `SidebarTabId` enum (all seven ids, schema-stable; `Layout.sidebar.tab` persists the active one); `src/renderer/features/shell/sidebarTabList.ts` is the static registry (renamed from `sidebarTabs.ts` on 2026-10-06: on Windows `./SidebarTabs` resolved to it instead of `SidebarTabs.tsx`; `src/main/sourceNames.test.ts` now refuses module names that differ only in case) (`SIDEBAR_TABS`, Manuscript only until later features append their entry) and `SidebarTabs.tsx` the ARIA tab bar + tabpanel; `ManuscriptTab.tsx` composes the tree and the create bar. A persisted id with no registered tab falls back to the first tab at render. `Layout` requires the tab (so the IPC input and output types match); `StoredLayout` in `src/shared/layout.ts` is the lenient reader the app-state file uses, defaulting a pre-F-7.3 file to Manuscript.
- Tags (F-4.1): `src/shared/tags.ts` is the one owner of the seven `TAG_CATEGORIES` (camelCase keys), `TAG_CATEGORY_LABEL`, `DEFAULT_CATEGORY_COLOR`, `HEX_COLOR`, `TAG_NAME_MAX`, and `toTagName` (kebab-case; letters and digits of any script are kept, so "Zoë" stays "zoë"). Schema: `tag` (name unique after normalization; `parent_id` self-reference, `ON DELETE SET NULL`) and `document_tag` (node↔tag link, unique pair, cascades from both sides; empty until F-4.4/F-4.6 write it) in migration `0002_tags`. `src/main/tag/tagStore.ts` mirrors the tree store: `listTags`, `getTagWithUsage`, `createTag`, `updateTag` (partial patch; cycle check walks `parentId` up), `deleteTag`; `usageCount` is derived with a `COUNT` join, never stored. Channels `tag:list`/`tag:create`/`tag:update`/`tag:delete` (and the event `tag:changed`, a tag created or renamed by an entity write, F-9.4); errors `VALIDATION` (empty after normalization, self/descendant parent), `ALREADY_EXISTS` (name collision), `NOT_FOUND`. `migrate.test.ts` hard-codes the bundled migration count, so every new migration bumps it.
- Tag Manager (F-4.2): `src/renderer/features/tags/tagStore.ts` is the renderer owner of the bank (`byId`/`ids` ordered by name then id like `tag:list`; generation-guarded `load` on project open and `clear` on close from `App.tsx`, the tag load never blocks the tree; `create`/`update`/`remove` await main and merge the returned row, never re-list; `resetTagStore()` in tests). A tag created through the raw bridge (e2e) is invisible to the store until the next load. `TagsTab.tsx` composes the category strip (ARIA tablist over `CATEGORY_FILTERS` from `categoryFilter.ts`, where `'all'` is a UI-only filter and `defaultCategoryFor('all')` is `custom`), the search, `TagList.tsx` (`role="list"` of button rows; the color dot is the one inline style), `TagForm.tsx` (keyed on the filter so category and color re-default; a hand-picked color survives a category change), and `TagDetail.tsx` (labels stacked above controls so the sidebar minimum never overflows; inline rename keyed on the name so the field re-syncs to the kebab-cased result; color drag steps coalesce to one write in flight plus the latest pick; delete via `dialogs.confirm` danger). Filter, query, and selection are component state. No nesting UI (`parentId` is never sent). The create form's bottom row wraps so the sidebar minimum (15 %) never overflows; check new sidebar content at that width in a 1024 px window (tabpanel `scrollWidth` vs `clientWidth`; the resize handle deliberately straddles the border, so measure the panel, not the `aside`).
- Tag templates (F-4.3): `src/shared/tagTemplates.ts` is the one catalogue (`TAG_TEMPLATE_IDS`, `TAG_TEMPLATES`: Standard Fiction, Mystery, Fantasy, Sci-Fi, each 4–8 kebab-case tags per non-custom category, colors always the category default). `loadTagTemplate` in the main tag store is one transaction that reuses `insertTag`, skips by normalized name across the whole bank, and returns `{ created, skipped }` in template order through `tag:loadTemplate`. The renderer store's `loadTemplate` merges `created` in one `set`; `TemplateLoader.tsx` (select + Load, above the search in the list view only) confirms via `dialogs.confirm` and toasts the counts.
- Custom tag templates (F-4.11; no migration): `src/shared/tagTemplates.ts` also owns `CustomTagTemplate` (`id`, `name` ≤ `CUSTOM_TAG_TEMPLATE_NAME_MAX` 80, `tags`: 1–`CUSTOM_TAG_TEMPLATE_TAGS_MAX` 2,000 `TagExchangeRecord`s, so color, category incl. custom, parent by name, and tracking travel), `CUSTOM_TAG_TEMPLATES_MAX` 50, `customTemplateNameKey`, and `keepTemplateRecords` (nulls a parent outside the kept set). Stored app-wide as `AppState.tagTemplates` (defaulted `[]`). `src/main/tag/customTemplates.ts` holds the pure list edits (`addCustomTemplate`, `updateCustomTemplate` rename/keep, `removeCustomTemplate`; ALREADY_EXISTS by name key, VALIDATION for no tags or the cap, NOT_FOUND). Channels `tagTemplate:list|save|update|delete` (save reads `exportTagBank`, filtered by `tagIds`) and `tag:loadCustomTemplate` (an `importTagBank` of the records, then the same rescan/proposals/spelling follow-ups as `tag:import`). Renderer: `customTemplateStore.ts` (app-level, `ensureLoaded` once, upserts sorted by name; `resetCustomTemplateStore` for tests), `tagStore.loadCustomTemplate` (shares `mergeCreated` with the template load and the import), `TemplateLoader.tsx` (select values `builtin:<id>` / `custom:<id>` under Built-in / Your templates optgroups; Save bank as template…, Manage…), `templateName.ts` (`promptTemplateName`, shared with the bulk bar's Save as template…), `TagTemplatesDialog.tsx` (rename, Edit tags removes one at a time with the last disabled, Delete after a confirm), `loadSummary.tagsLabel`.
- Tag bulk operations and exchange (F-4.9): `src/shared/tagExchange.ts` owns the file (`TAG_EXCHANGE_FORMAT_ID` 'mythscribe-tags', version 1, `TagExchangeRecord` `{ name, category, color, parent (by name), trackMentions }`, `serializeTagBank`, `parseTagBank` — kebab-cases names, drops repeats, throws `TagExchangeError { row }`) and the merge aliases (`TAG_ALIASES_KEY` in the settings KV, `TagAliases` merged-away id → target id, `resolveTagId`, `mergeAliases`, `dropAliasesTo`). Main `tagStore.ts`: `deleteTag`/`deleteTags` share `removeTags` (all ids checked first; AI-made names join the dismissed proposals; aliases leading to a deleted tag are dropped), `recolorTags`, `mergeTags` (links move, a node carrying both keeps one link and `author` wins; dismissals move unless the node carries the target; entities re-point and are announced as `entity:changed`; target keeps name, color, origin), `exportTagBank`, `importTagBank` (skips taken names; parents linked by name in a second pass, a cycle skipped). `src/main/tag/tagExchange.ts` reads and writes the file (`writeTextAtomic`); `dialogs.chooseTagBankFile`. Inline tokens are never rewritten: `tokenTag(id, byId, aliases)` in `InlineTag.ts` resolves them for paint (`resyncInlineTags(dom, byId, aliases)`), `renderHTML`/`renderText`, Open in Tag Manager, and the tag bar's inline counts. Renderer: `tagStore` holds `aliases` (loaded with `tag:list`; every stub answering `tag:list` must answer `tag:aliases`), `recolorMany`/`removeMany`/`mergeInto`/`importBank`/`exportBank`; `TagBankActions.tsx` (Import…, Export…, Select toggle) and `TagBulkBar.tsx` (count, All/None/Done, color on pick coalesced like `TagDetail`, Delete and Merge with danger confirms); select mode prunes the checked set to the visible rows at render and hides the template row; `loadSummary.ts` is shared by the template loader and the import toast.
- Document tag bar (F-4.4): `src/main/tag/documentTagStore.ts` (`listDocumentTags`, `addDocumentTag`, `removeDocumentTag`; idempotent, transactional, documents only via the node row's `kind`, return the tag with its fresh `usageCount`) behind `documentTag:list`/`add`/`remove`. Renderer: `src/renderer/features/tags/documentTagStore.ts` owns `tagIdsByNode` (per-node load tokens, cleared on project close); `add`/`remove` merge the returned tag into the bank (`useTagStore.merge`, re-sorts only on a name change) before splicing the ids, so the Tags tab's counts move without a reload and chips always render the bank's record (rename/recolor shows at once). - Automatic mentions (F-4.12): `src/shared/mentions.ts` owns `MENTION_DEBOUNCE_MS` (1500), `MentionRange`, `TagMentions`, `nameWords`, `MentionCandidate`, and `findMentions(doc, candidates)`, a pure scan over the stored Tiptap JSON that answers ProseMirror `[from, to]` ranges (its own position walk: a container costs 1 before and after its content, text its length, a leaf 1; `LEAF_TYPES` must match the editor schema in `extensions.ts`). Schema (migration `0008_mentions`): `tag.track_mentions` (default on), `tag_mention` (`<tag_id>:<node_id>`, `count`, `positions` JSON, cascades both ways), `mention_scan` (`node_id` PK, `content_hash`). Channels `mention:listForTag` (NOT_FOUND for an unknown tag) and `mention:listForNode` (NOT_FOUND for an unknown node). Renderer: `src/renderer/features/tags/mentionStore.ts` (`byTag`/`byNode`, per-key load tokens, one idempotent `subscribe()` to `mention:changed` opened in `App.tsx` on project open that refetches the named loaded nodes and every loaded tag, a failed refresh keeps the rows on screen; `clear` on close; `resetMentionStore()` for tests). `src/renderer/features/editor/openPassage.ts` holds `openPassage(nodeId, locate)` (extracted from `assistantStore.openScene`, which now wraps it; `PASSAGE_GONE_MESSAGE` and `OPEN_SCENE_TIMEOUT_MS` live here and are re-exported there), `editorFor`, and `openMention(nodeId, range, name)` (the stored range when `textBetween` still reads as the name, else `locateText(doc, words, { ignoreCase: true })` — the one caller of that flag). `TagDetail` shows `Track mentions`, "Mentioned in N documents", and a "Documents mentioning this tag" list in tree order (via `tagFilterView` fed the mention rows as links) with `×count` and a jump; `TagsPanel` shows a `Mentions` list after `Inline tags` (`MentionRow`: dot, name, `×count`, "Jump to first mention of <name>"); both render nothing for a tag the bank does not hold, so a tag created through the bridge only shows once the Tags tab has loaded the bank (the e2e creates its `Rose` through the form for that reason). - Entities (F-9.1): `src/shared/entities.ts` is the one owner of the three `ENTITY_KINDS` (`character`, `setting`, `world`; `ENTITY_KIND_LABEL`, `ENTITY_KIND_NOUN`), the two `ENTITY_TEMPLATES` (`structured`, `blank`), `ENTITY_FIELD_IDS` and the per-kind `ENTITY_FIELDS` (`{ id, label, multiline }`: character age/born (F-11.2b)/gender/appearance/personality/background/goals/relationships/notes; setting type/description/atmosphere/features/associatedCharacters/notes; world category/description/rules/impact/notes — `name` and `image` are columns, not fields), `ENTITY_KINDS_WITH_IMAGE` (`kindHasImage`), `WORLD_CATEGORY_SUGGESTIONS` (free text; suggestions only), the limits (`ENTITY_NAME_MAX` 200, `ENTITY_FIELD_MAX` 20 000, `ENTITY_BODY_MAX` 200 000), `fieldIdsFor`, `isFieldOf`, `toEntityNameKey` (NFC, trim, whitespace collapsed, lower-cased: the uniqueness key), and `parseEntityFields(raw, kind)` (tolerant: null, bad JSON, unknown keys, non-strings, and `''` all read as no value). Schema (migration `0009_entities`): one `entity` table (`kind`, `name` as typed and trimmed, `template` default `structured`, `fields` JSON default `{}`, `body` nullable, `image` nullable — an asset file name F-9.3 writes —, `tag_id` nullable FK → `tag` `ON DELETE SET NULL` — F-9.4 writes it, so a deleted tag leaves the entity tagless —, `created`, `modified`; index `(kind, name)`; no CHECK on `kind`, like every other enum column). Names are unique per kind on the key, enforced in the store's write transaction, not by an index (SQLite `lower()` is ASCII-only). `src/main/entity/entityStore.ts` mirrors the tag store: `listEntities` (sorted in memory: kind order, then name key, then id), `getEntity` (undefined; the handler raises NOT_FOUND), `createEntity`, `updateEntity` (`fields` merged over the stored map, `''` removes a key, so the column never carries an empty value; `kind` is immutable), `deleteEntity` (the linked tag stays). Channels `entity:list`/`entity:get`/`entity:create`/`entity:update`/`entity:delete`; `fields` is `z.partialRecord(EntityFieldId, …)` so an unknown id is refused at the contract and a known id of the wrong kind is the store's VALIDATION; ALREADY_EXISTS on a name clash within the kind. The image upload channel and `assets/entities/` are F-9.3, the tag link is F-9.4 (`createEntity`/`updateEntity` answer `EntityWrite { entity, tagChange }` since then).
- Entity tabs (F-9.2): `src/renderer/features/entities/entityStore.ts` is the renderer owner of the story bible, the tag store's pattern (`byId`/`ids` in `entity:list` order: kind, `toEntityNameKey`, id; generation-guarded `load` on project open and `clear` on close from `App.tsx`; `create`/`update`/`remove` merge the returned row; `resetEntityStore()` in tests) plus session-only view state: `view` per kind (`list` | `cards`, cards by default, not persisted) and `selectedId` (the picked row; `remove` clears it; F-9.3 opens it in the editor). `entityView.ts` holds the pure helpers `matchesQuery` (name, every field, body), `excerptOf` (first filled template field in order, skipping the World category, else the body; ≤ `EXCERPT_MAX`), and `categoriesOf`. `EntityTab.tsx` (`{ kind }`) is one component for the Characters, Settings, and World tabs, registered three times in `features/shell/sidebarTabList.ts`: search box + `role="group"` List/Cards toggle (`aria-pressed`), a Category `<select>` on the World tab once a category is in use, `EntityList.tsx` (`role="list"` labelled by the kind; the row button toggles the selection with `aria-current`; the trailing "Delete <name>" button confirms through `dialogs.confirm` danger, visible on hover/focus), and `EntityQuickAdd.tsx` (name only, structured template; a refusal toasts and keeps the name). - Entity editor (F-9.3): `src/shared/assets.ts` is the one owner of the asset scheme (`ASSET_SCHEME`, `ASSET_DIRS` `backgrounds | entities | references` (the last since F-9.6), `IMAGE_EXTENSIONS`, `IMAGE_MAX_BYTES` 20 MB, `imageExtension`, `assetFileName(original, shortId, fallbackStem)`, `assetDisplayName`, `assetUrl(dir, file)`); `focus.ts` keeps its `BACKGROUND_*`/`background*` names as aliases over it, and `entities.ts` adds `ENTITY_IMAGES_DIR` (`entities`) and `entityImageUrl(fileName)`. - e2e race seen 2026-10-01 (F-9.6), twice in four runs: after the F-9.4 "jump to scene" row click, `editor.click()` + `End` could land while the jump was still settling, the name stayed selected, and the Backspaces ate the wrong text (`"… Th waited."`).
