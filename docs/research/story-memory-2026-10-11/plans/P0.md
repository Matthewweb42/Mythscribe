# P0 Ground truth: implementation plan

**Features:** F-16.1, F-16.2 and F-16.3 (`FEATURES.md` §2.16). Phase P0 of the story memory redesign, approved by the author on 2026-10-11 (`../design.md`, Part 4). **Size:** S, about 4 days. **Status:** built, reviewed and ticked 2026-10-11; the author's probe run (§3) is still open.

**Goal:** real prices and safe plumbing before any story-memory code exists. P0 adds no AI feature id, no prompt, no v2 UI and no change to how v1 behaves, apart from four things an installed build will notice:
1. Cost estimates use the corrected prices.
2. On Cloud, fast-tier requests on V4 Flash run with reasoning off.
3. The usage ledger gets two nullable columns.
4. The Usage history shows thinking tokens.

All of it is launch-safe on its own.

**Build order:** F-16.2 first (plumbing, no AI), then F-16.3 (the probe uses the test book), then F-16.1. Each feature is one `/feature` commit with its own gate run, and the full gate suite runs at most twice per feature. Each feature commit adds or updates its bullet in `docs/ARCHITECTURE.md`.

## 1. F-16.2 Safe plumbing

### 1.1 Lenient feature ids and route actions (do this first)

**Why.** Retiring an id at the switch-over (`tags`, `summary`, `continuity`, `organise`, `todo`, `sheetSync`, `query`, `route`) would break two stored rows today:
- **AI settings.** A project's AI settings row fails to parse, because zod's `partialRecord(AiFeatureId, …)` refuses unknown keys (checked: `unrecognized_keys`). The row then falls back to the defaults, which turns Use AI off for every project.
- **Conversations.** A stored chat turn whose `action` is no longer a `RouteAction` (for example `continuity`) fails `Conversations`. `parseStoredConversations` then returns `defaultConversations()`, which wipes the chat history.

There is a third problem on the wire. The Worker parses `feature` with the app's own `AiFeatureId` enum, so a newer app's new id (`reader`) is refused by an older Worker.

| Change | File |
|---|---|
| `lenientFeatureRecord(value)`: `z.record(z.string(), z.unknown())`, filtered to known `AiFeatureId` keys whose value parses, then piped to `z.partialRecord(AiFeatureId, value)`. One helper. | `src/shared/ai.ts` |
| `LenientTierTable` becomes `lenientFeatureRecord(Tier)` (reuse, not a second copy) | `src/shared/aiRouting.ts` |

## 2. F-16.3 The test book and the memory invariants

### 2.1 Pure helpers (`src/shared/memory/`, shared so the renderer can draw underlines from anchors in P4)

| File | What it does |
|---|---|
| `sentences.ts` | `splitSentences(text): SentenceSpan[]` (`start`, `end`, `text`) over `straightenQuotes` text. It handles abbreviations (Mr, Mrs, Ms, Dr, St, Capt, Col, Lt, Rev, Sgt), initials, ellipses, `?!`, closing quotes after terminal punctuation, dialogue tags (`"Go," she said.` stays one sentence) and em dashes. |
| `quote.ts` | `QUOTE_MIN_WORDS = 3` and `QUOTE_MAX_WORDS = 25`. `locateQuote(paragraphs, p, quote)` returns `QuoteLocation` (`p`, offsets, sentence indexes) or `QuoteMiss` with a reason: `tooShort`, `tooLong`, `notFound`, `otherParagraph` or `repeated`. It reuses `normalizeForMatch` from `src/shared/critique.ts` and is case-sensitive. The quote must sit exactly once in the whole window, and that once must be in paragraph `p` (design §2.3 ladder, step 1). |
| `anchor.ts` | `sentenceHash(text)`: `normalizeForMatch`, then cyrb53, as 14 hex characters. It is pure JS so main and the renderer agree, and collisions do not matter at book scale. `sceneSentences(paragraphs)` returns a flat list with paragraph indexes. `anchorFor(sentences, location, namingSentence?)` hashes the quote's sentences ±1 across paragraph boundaries, plus the naming sentence for a pronoun subject. `anchorHolds(anchor, present: ReadonlySet<string>)`. Names stay in the sentence text: Rename in book (F-16.13) rewrites anchors, and only the reading gate's hash leaves names out. |
| `sources.ts` | `MEMORY_SOURCES` lists `scene`, `pinned`, `note`, `research`, `synopsis`, `brief`, `sceneNote`, `plannedCard`, `idea`, `try`, `chat`, `inactiveDraft`, `ideaScene`, `excludedScene` and `notCanon`. `meaningOf(source, { order, openOrder })` returns `happened`, `later`, `canon`, `plan` or `never` (design §2.2 "Meaning by place"). `readerMayRead(source)` is true for `scene` only. |
| `invariants.ts` | `checkMemoryInvariants({ claims, sceneHashes, aliases, citations })` returns `InvariantViolation[]`, a discriminated union of six violations (listed below). The input row types are minimal (`InvariantClaim`, `InvariantAlias`, `InvariantCitation`), so P2a maps its own tables onto them without importing P0 types into the schema. |

The six violations `checkMemoryInvariants` reports:
- `anchorMissing`: a live claim whose anchor hashes are not all present in its scene;
- `anchorEmpty`: a live claim with no anchor at all (added after review: an empty anchor holds vacuously and could never go stale);
- `unproved`: a claim whose proof is neither `literal` nor `verified`;
- `aliasClash`: one unshared `norm` belonging to two records;
- `unreadableSource`: a claim from anything but `scene`;
- `citesCard`: an answer citing a card.

**Tests** sit beside each file:
- abbreviation and dialogue splits;
- curly quotes;
- a quote that occurs twice is `repeated`;
- a quote in the wrong paragraph is `otherParagraph`;
- anchors that cross a paragraph boundary;
- editing one sentence breaks only the anchors that cover it;
- each violation kind once, plus a clean case.

### 2.2 The test book (`src/main/memory/testBook/`, test data only, never bundled into the renderer)

| File | Contents |
|---|---|
| `book.ts` | `TEST_BOOK`: scenes with `id`, `chapter`, `title` and `paragraphs: string[]`; optional typed details (POV, place, time, year); a `source` (`scene`, `ideaScene`, `inactiveDraft` or `excludedScene`); and a header listing the disguise and the public-domain source (*Pride and Prejudice*, Jane Austen, 1813, Project Gutenberg eBook #1342). |
| `labels.schema.ts` | zod `TestBookLabels`, described below |
| `labels.ts` | `TEST_BOOK_LABELS`, parsed by the schema in its test |

`TestBookLabels` holds:
- records, with aliases, kind and a shared flag;
- expected claims (scene, `p`, record, slot, value, quote, voice, mode), each marked `expect: literal | verified | reject` with a one-line reason;
- mentions per scene;
- twin-gate cases (`blocked` or `new`, and what blocks them);
- knows lines (secret, learner, how, from, scene, quote);
- planted contradictions (rule, two quotes);
- "must not produce" negatives.

**Text** is about 8,500 words in all.
- **Disguised Austen (about 6,000 words).** Excerpts of chapters 1–3, 6 and 18, with every name and place changed (Bennet → Harrow, Elizabeth → Liesel "Lise", Darcy → Callum Varrow, Bingley → Ned Ashby, Netherfield → Thornmere, Longbourn → Wexley, Meryton → Callow Cross, and so on). Several facts change too: four daughters instead of five, Ashby's income, and Varrow's eyes. A model that answers from memory of the novel therefore answers wrongly, which shows up in scoring.
- **Original hard cases (about 2,500 words, written for this book):**
  1. a pronoun trap with two women in a room (the claim must wait);
  2. a character known only as "the Captain";
  3. a lie in dialogue that contradicts earlier narration (voice is dialogue, so no C1);
  4. a memory ("She remembered her mother's red hair");
  5. negations ("His eyes were not blue": reject literal proof);
  6. a shared surname (Mr and Mrs Harrow: wait);
  7. a secret's originator, with the secret overheard (knows: `overheard`, from whom);
  8. a time skip ("Three winters later"), with a typed year;
  9. a dream ("In the dream, Johanna was dead": no C2);
  10. an Idea-status scene and an inactive-draft variant (never read);
  11. a planted C1 (grey eyes, then brown), C2 (a dead man Here) and C3 (tells before learning).

**Tests (`testBook.test.ts`):**
- the labels parse;
- every expected claim's quote is located by `locateQuote` exactly once in its paragraph (the helpers' integration test);
- both quotes of every planted contradiction are found;
- every never-read scene is refused by `readerMayRead`;
- no paragraph exceeds 2,500 estimated tokens;
- none of the original names (Bennet, Darcy, Bingley, Elizabeth, Netherfield, Longbourn, Wickham, Meryton, Lucas) appears anywhere in the book.

**How later phases use it.** It feeds P2a's `reader.v1` and `verify.v1` eval cases, and the live planted-error run that is P2a's merge condition, scored per slot. P2b uses the knows labels, and P4 uses the planted contradictions and negatives.

- **Cache:** 4 requests that share a 2,000-token prefix (the rules plus one test-book scene, F-16.3) with a varying tail, `max_tokens` 16 and reasoning off, at least 2 s apart.

That is 26 calls, about 5¢ at list prices. The run stops if the running reported cost passes $0.25.

**Output:**
- `docs/research/story-memory-2026-10-11/probe/ai-probe-<date>.md`, the report;
- `ai-probe-<date>.json`, the raw numbers (no prompt text, no key);

The report recommends:
- the cached price;
- each model's reasoning entry (whether Pro thinks by default, and whether Flash `off` saves anything);
