# P1 Names and documents: implementation plan

**Features:** F-16.4 to F-16.15 (`FEATURES.md` §2.16). Phase P1 of the story memory redesign, approved by the author on 2026-10-11 (`../design.md` §2.2, §2.6, §2.7, §2.10, Part 3, Part 4; `../author-answers.md` answers 2, 3, 7, 9, 16, 19, 22, 23, 24; decisions 3, 6 and 8). **Size:** L, about 3 weeks, in six slices. **Status:** planned 2026-10-11. Slice 1 built 2026-10-11 (data layer; see `QUESTIONS.md` for the calls made while building). Slice 2 built 2026-10-11 (the Research section and the page schema; calls in `QUESTIONS.md` "P1 slice 2") and reviewed (fixes: a page's original is never the Library's, AI marks clear only when the words change, Not canon headings, the agent run without Research, no notes pad or tags column on a Research page, plan links asserted). Slice 3 built 2026-10-12 (sheets, labels, typed details and the v2 shell; calls in `QUESTIONS.md` "P1 slice 3"; two read channels the plan did not list, `label:links` and `names:byRecord`, which the label filters and *Named in* need) and reviewed (fixes: shared nicknames from the sheet, *Named in* jumps for hyphenated names, Pinned and Ideas in the crash journal, a v2 window drop into Research through `research:addData`, `record:changed` narrowed with `roster` and no push on a page save, the tag menu items left out of a v2 menu, *New character…*/*New place…* in the POV and Place pickers, labels described as filters until slice 5). Slice 4 built 2026-10-12 (the This scene | Book panel, Needs a look, Dismissed, Rename in book, the agent in v2; calls in `QUESTIONS.md` "P1 slice 4"; Rename in book is offered from a name's chip in the panel too, so the open scene changes in its editor; the agent also refuses a sheet or tag delete and the upload dialog in v2; the agent's and proofread's `sendsV2` data-sharing rows ship here, the rest in slice 5). Slice 5 built 2026-10-12 (the Story notes block in 11 v2 prose versions, filing a Research page into Pinned with `contextImport.v3` and `reviewChat.v3`, filed-line conflicts in Needs a look, migration `0033_research_filed`; calls in `QUESTIONS.md` "P1 slice 5"; two write channels the plan did not list, `research:keepFiledLine` and `research:updateFiledLine`, which *Keep line* and *Update line* need; `editPass.v3` carries the block for the continuity pass only). Slice 6 built 2026-10-12 (the switch-over flow on copies and the imports in v2; no migration; calls in `QUESTIONS.md` "P1 slice 6"; the safety step runs when the author presses Convert, just before the only write, rather than before the dry run; the trial copy gets its own project id and name so its backups never mix with the original's; `switchover:available` is a fifth channel the menu needs; `ProjectManager.newProjectMemory()` decides the memory of a project an import or a v0 conversion makes).

**Goal:** records and names replace tags, the author's own documents get a home (Research), and everything that works without AI works in v2: names and nicknames, mentions, word search, one-view sheets, labels, the This scene panel's AI-off parts, to-dos and one Dismissed list. The prose prompts get the Story notes block. The switch-over is built and tested on copies only. There is no reader yet (P2a), so no claims, cards, True now, Read now or underlines.

**Rules that hold in every slice:**
1. **Everything is behind `storyMemory === 'v2'`.** v1 behaviour for installed users stays byte for byte as it is. Section 0 lists how that is enforced and tested.
2. **Migrations are additive only:** new tables, new nullable columns, and a hand-written FTS table. Nothing is dropped or rewritten until P9 (F-16.38). The copy from tags, entities and `context_file` into the new tables happens in the switch-over conversion (slice 6), not in a migration (decision P1-D1 below).
3. **Until P3, v2 runs `agent.v8` unchanged,** with its tag and sheet tools refused in code (slice 4).
4. Tag, entity, knowledge, Organise and To do code is frozen for edit lists. P1 changes those files only to add a v2 early-out, never to change v1 behaviour.
5. Each prompt version ships with a golden test, eval cases, a token-report row and its `aiCostNotes.ts` note, with one `npm run eval:ai -- -u` run per slice. The commit quotes the token-report diff.
6. Lint per folder (`npx eslint src/shared`, `src/preload`, `src/main`, `src/renderer`, `cloud`, `e2e`, `scripts`). The full `npm run lint` runs out of memory on this machine. The full gate suite runs at most twice per slice.
7. Each slice adds or updates its bullet in `docs/ARCHITECTURE.md`, records its open calls in `QUESTIONS.md`, and marks progress in the F-16.x text. A feature is ticked only in the slice that completes it (§8).

**Build order:** slice 1 (data layer) → 2 (Research and the page schema) → 3 (sheets, labels, typed details, the v2 shell) → 4 (the panel, Needs a look, Dismissed, Rename in book, the agent in v2) → 5 (prompts: the Story notes block and filing) → 6 (the switch-over flow on copies, and imports). Each slice can be built, gated and committed on its own.

## 1. Slice 1: records, names, labels and the local index (data layer; F-16.4, F-16.5, and the tables of F-16.7, F-16.10, F-16.11)

### 1.1 Migrations

`0029_story_records` (generated from `schema.ts`):

| Table | Columns |
|---|---|

Unique (`record_id`, `norm`); a partial unique index on `norm WHERE shared = 0`; an index on `norm`. |
| `label` | `id`, `name`, `colour` (`#rrggbb`), `kind` (`tone`, `content`, `theme`, `custom`), `position`, `legacy_tag_id`, `created`, `modified`. Names are unique case-insensitively, enforced in the store as entity names are. |
| `label_link` | `label_id`, `node_id` (both FK cascade); PK on the pair; index on `node_id`. Scenes and Research documents. |

| `scene_detail` | `node_id` (PK, FK cascade), `pov_record_id` and `place_record_id` (FK set null), `place_text`, `time_text`, `story_year` (integer, null), `also_here` (JSON array of record ids; an id with no record reads as gone), `modified`. |

`0030_name_index` (generated):

| Table | Columns |
|---|---|
| `name_mention` | `id`, `node_id` (FK cascade), `record_id` (FK cascade), `para`, `from`, `to` (ProseMirror positions of the saved document, as `tag_mention` stores them, so jumps reuse `openMention`), `text`, `ambiguous`, `span_key` (`para:from`; groups the candidate rows of one ambiguous span). `0031_memory_passage_fts` (custom, written by hand like 0022): `CREATE VIRTUAL TABLE memory_passage_fts USING fts5(source UNINDEXED, owner_id UNINDEXED, para UNINDEXED, canon UNINDEXED, text, tokenize='porter unicode61 remove_diacritics 2')`.

Why typed details get their own table, not new `SceneMeta` keys: `SceneMeta` is a `z.object`, which strips unknown keys, so an older build saving scene meta would silently drop them. Older builds never touch a table they do not know.

### 1.2 Shared vocabulary and pure rules (`src/shared/memory/`, beside P0's helpers)

| File | What it holds |
|---|---|
| `records.ts` | `RECORD_KINDS` (`character`, `place`, `thing`, `group`, `term`, `secret`, `thread`). `recordKindOf(categoryId)` maps character→character; setting→place; faction→group; thread→thread; magic, religion, culture, history, language, technology, lore→term; world, item, creature and every custom category→thing. `RECORD_ORIGINS`, the `Record` and `RecordAlias` zod schemas, and the caps (reusing `ALIAS_MAX`, `ALIASES_MAX`, `ENTITY_NAME_MAX`). |
| `names.ts` | `normName(text)` straightens quotes, applies NFC, collapses spaces, strips a possessive and lower-cases. `TITLES` holds Mr, Mrs, Miss, Ms, Dr, Lord, Lady, Sir, Dame, Captain, Capt, King, Queen, Prince, Princess, Father, Mother, Brother, Sister, Master, Mistress, Professor, General, Colonel, Lieutenant, Sergeant, Commander, Uncle, Aunt and the like. `foldTitles(words)` is for the twin gate only. `capitalisedSpans(paragraph)` returns the longest capitalised spans, with link words inside a span (of, de, van, von, the…, reusing the `LINK_WORDS` idea in `tagTerms.ts`), a sentence-start flag (via `splitSentences`), the possessive stripped (`wordsIn` from `storyNames.ts`), and a leading sentence-start `STOPLIST` word dropped ("The Captain" gives "Captain"). |
| `twinGate.ts` | `twinGate(candidate, roster, dismissedNames)` returns `clear`, or `blocked` with a reason (`alias`, `subset`, `prefix`, `edit` or `dismissed`), the record it points to and the matched name. The rules, in design §2.2 rule 5 order: an alias matches after folding (case, diacritics, titles, possessive); a word subset once titles are removed, either way; a prefix of an existing name word of 4+ letters (candidate at least 2 letters); edit distance 1 from a 5–7-letter name or 2 from an 8+-letter one (`editDistance` from `storyNames.ts`); a name on Dismissed (silent). `twinPairs(roster)` lists the pairs the gate blocks among existing records, for the switch-over merge list. |
| `nameScan.ts` | `buildNameIndex(records, aliases)` and `scanNames(paragraphs, index, ctx)` return `NameMention[]`. It is pure and implements identity rules 1–4: a mention is a whole capitalised span equal to a known name or alias (so "Jem Falsire" is not Falsire), possessives count, and a plural points to a group or stays ambiguous. `exact` names, and `auto` names the text also writes in lower case ("Will"/"will", read from the scene itself, as `tagTerms.ts` does), match only in their exact case, and at a sentence start only if the scene names the record elsewhere mid-sentence. `any` names (typed in lower case by the author) match on word boundaries in any case. Shared aliases are resolved when the paragraph or its neighbours (±1) name exactly one owner, or one owner is the typed POV. Otherwise every candidate gets an `ambiguous` row. Not-a-mention phrases are skipped. |
| `passages.ts` | `PASSAGE_SOURCES`, a subset of `MemorySource`: `scene`, `sceneNote`, `pinned`, `idea`, `note`, `research`, `ideaScene`, `excludedScene`. `PassageCanon` is `canon` or `notCanon`. `passageLabel(source, canon)` gives `notCanon` when marked, else the source (feeding `meaningOf`). |
| `nameQuestions.ts` | `nameQuestions(counts, roster, dismissed)`. A recurring unknown capitalised name (mid-sentence, at least twice, not on `STOPLIST`, reusing `countCapitalisedWords` and `opensSentence` from `proposedTags.ts`) that the gate clears becomes a `newName` question ("Hesk: named in 5 scenes"). One the gate blocks against a record becomes a `nickname` question ("Is 'Ry' Rynna Falsire?"). A dismissed one never appears. At most 10, most-named first. |
| `src/shared/storyLabels.ts` | `LABEL_KINDS`, the `Label` schema, colour defaults (tone and content keep the tag colours), and `labelSteerLines(labels)`, used by slice 5. (`labels.ts` is taken: it is the section vocabulary.) |
| `dismissed.ts` | `DISMISSED_KINDS`: `name`, `alias`, `notMention`, `split`, `notSame`, `unlink`, `notRight`, `notProblem` (the last three written from P2a/P4). `dismissedKey(kind, parts)` returns the one key shape per kind, for example `notMention`: `recordId\|norm(span ±1 word)`. The `Dismissed` schema. |
| `authorTodo.ts`, `sceneDetails.ts` | Zod schemas and caps. `SceneDetails` holds `povRecordId`, `place: { recordId, text }`, `time: { text }`, `storyYear` and `alsoHere`. |

### 6.2 What converts (design Part 3, answer 16)

**Kept and converted:**
- **Records.**
  - Every author entity becomes a record (category, image and aliases kept; `legacy_entity_id`).
  - Name-category author tags without an entity also become records (character, setting, worldBuilding; their aliases, through `legacy_tag_id`).
  - Plot-thread tags become thread records.
  - A tag linked to an entity merges into that entity's record.
- **Pinned.**
  - Filled fields (the category template, then `extraFields`) become "Label: value" lines.
  - Dated author facts become "Label (from 12.1 'Title'): value".
  - Author relationships become "Relationship: <text> <name>".
  - A blank page's author paragraphs become Pinned paragraphs.
  - Sheets marked Plan or Idea go into **Ideas** instead.
- **The Project notes sheet** becomes a written Research note "Project notes", Not canon when it was marked Plan or Idea.
- **Labels.** Tone, content and custom tags become labels (colour kept, nesting dropped and listed). Their author links become `label_link` rows. Custom tags become custom labels, which no longer steer prose; the dry run says so and the kind can be changed to Theme (decision P1-D6).
- **Typed details.**
  - `scene_meta.pov` and `location` strings become record ids by name or alias. Location text is kept in `place_text`. A POV with no record is listed, and a Character is created for it.
  - The timeline text is kept in `time_text`.
  - A timeline event's year goes on the first scene of each run of consecutive scenes linked to that event.
  - An author link of a character or place tag on a scene that does not name the record becomes *+ also here* (decision P1-D5).
- **Uploads** become Research documents with their originals (§2.2).
- **Dismissals that still apply.**
  - Proposed-name and dismissed-sheet names become `name`.
  - A kept spelling between two names that both become records becomes `notSame`.
  - Plan-link dismissals become `unlink`.
- Scene notes and Idea scenes are untouched.

**AI-written sheet text (decision 8)** goes into a "Filed by AI earlier: please check" heading paragraph plus the paragraphs under it, every one marked `notCanon`, at the end of Pinned. It is found two ways:
- a field whose value still equals the `after` of its latest applied `restoreSheet` change from the `library`, `organise`, `chat` or `sync` sources;
- a sheet made by those sources whose `modified` has not moved since (`deleteSheet.modified`).

**Dropped (AI-made), listed by name:**
- AI facts and `observed_fact`;
- summaries and cards (they stay in their tables for v1 until P9);
- AI tags and AI links;
- sheets with `origin = 'ai'` holding only text the background reading wrote;
- page paragraphs in `sync.aiParagraphs`, which are write-ups of the fields already converted;
- Changes, findings, computed To do items, sync state and AI plan links;
- obsolete dismissals: AI-tag removals, observed-fact hides, To do, continuity and sheet-sync dismissals.

## 7. Decisions this plan makes (decided by Claude, unconfirmed; logged in `QUESTIONS.md`)

- **P1-D1.** The copy from tags, entities and `context_file` happens in the switch-over conversion, not in migrations 0029+. The installed app keeps running v1 after the migrations, so a migration-time copy would go stale with every later tag edit. Migrations create empty tables only.
- **P1-D2.** A record's names live only in `alias` (`is_main` marks the name), so a name has one owner. Not-a-mention phrases and alias removals live only in `dismissed`.
- **P1-D3.** "Dictionary word" is read from the manuscript (the name also written in lower case), since no word list ships (the `tagTerms.ts` approach). The gendered-title rule for shared aliases waits for P2a, because records carry no gender in P1.
- **P1-D4.** The author's own new record is warned about by the twin gate, never silently blocked. Silent blocking is for names the app proposes.
- **P1-D5.** An author's character or place tag link on a scene that does not name the record becomes *+ also here*.
- **P1-D6.** Custom tags become custom labels (local only). They steered prose as "Themes" in v1; the dry run says so and the kind can be changed to Theme.
- **P1-D7.** P1 ships `notesSuggest.v3` (the Story notes heading for scene suggestions). P2a's card re-point becomes `notesSuggest.v4`.
- **P1-D8.** In v2 the Timeline, Threads, To do, Changes, Index and Library sections are hidden from P1 on. Timeline years move into typed story years at the switch-over. The Book views return them in P2b–P4.
