# P3 Ms Scribe v9: implementation plan

**Features:** F-16.24, F-16.25 and F-16.26 (`FEATURES.md` §2.16). Phase P3 of the story memory redesign, approved by the author on 2026-10-11 (`../design.md` "Decisions (2026-10-11)" (decision 3 as the author changed it), §2.1, §2.2 (the four AI writes, meaning by place), §2.5 (absence is scoped), §2.6 (all of it), §2.7, §2.10, Part 4 (P3 row), Part 5; `../author-answers.md` answers 1, 3, 10, 11, 12, 13, 18, 19, 22). **Size:** M, about 1.5 weeks, in six slices. **Status:** planned 2026-10-13.

**Goal:** the chat answers from the book, cheaply and checkably. A question the memory already answers ("Mara's eyes?", "Does Orrin know about the sold map?", "Who knows about the sold map?") gets an **instant card** with no AI call. Every other turn goes through **Step 0** (local, under 50 ms) and **`navigator.v1`** (fast, at most 3 steps, evidence ids only), which also takes over `route.v2`'s routing in v2, keeping F-5.26's edit passes and every other route action. **`agent.v9`** then answers in one strong call from the whole open scene plus labelled evidence, citing `[E7 "quote"]`; code checks every quote, **`cite.v1`** checks the cited sentences and the scope of "first/last/ever/never" answers, an unsupported main claim retries once and then says "Not found in the manuscript (I looked in …)", and one **Self-Route** request may widen to a chapter (its finds logged as search misses for F-16.35). When the author asks, Ms Scribe puts a line on a record's sheet (decision 3 as changed by the author): Pinned when asked, Ideas for an idea, and "Is this an idea or canon?" when she cannot tell. The chat never writes claims.

**Rules that hold in every slice** (P1's, P2a's and P2b's, carried over):
1. **Everything is behind `storyMemory === 'v2'`.** A v1 project sends, stores and shows exactly what it does today: `route.v2` and `agent.v8` keep running there, their token-report rows do not move, and the smoke e2e (`e2e/smoke.spec.ts`, v1, which covers F-5.19, F-5.22 and F-5.26) is not edited. New channels are `v2` in `CHANNEL_MEMORY`; a v1 call of one is VALIDATION before the handler.
2. **Migrations are additive** (0037+). `migrate.test.ts` checks that every older table keeps its rows and columns.
3. **Each prompt version** (`agent.v9`, `cite.v1`, `navigator.v1`) is a new file with a golden test, eval cases, a token-report row, its `aiCostNotes.ts` entry (the planned rows move to shipped) and its data-sharing text, with one `npm run eval:ai -- -u` in the slice that ships it; the commit quotes the token-report diff. Reasoning: `navigator` and `cite` join `NO_REASONING_FEATURES` and `LOWEST_EFFORT_FEATURES`; `agent.v9` sets reasoning per turn (§2.4).
4. **No live run can happen in the build sessions** (no API key). The live Ms Scribe run is built so the author can run it with `OPENROUTER_API_KEY` (slice 6); every slice says so, and the final slice records the owed runs in `FEATURES.md` and `CLAUDE.md`.
5. **Absence is never a fact** (P2b rule 9 and P2b-D9 stand): nothing Ms Scribe is sent says someone does not know something, and `checkedUpTo` never reaches a prompt. The only absence wording is the renderer's scoped muted line on an instant "who knows" card (composed in `knowsView.ts`, as P2b does) and Ms Scribe's own scoped answer ("I found no scene where Tomas learns it (searched 1.1–14.2)"), whose scope code computes from what it searched (P3-D8).
6. **The chat never writes claims, cards or readings.** Its only writes are the manuscript edits it already had (Auto / Ask / Plan rules unchanged) and the sheet lines of F-16.26 (author-owned Pinned or Ideas paragraphs marked `aiWritten`). A test after every scribe path asserts the `claim`, `card` and `reading` tables are unchanged.
7. Tag, entity, knowledge, Organise and To do code is frozen for edit lists. P3 touches `agentToolsV2.ts` only to move its read helpers into the navigator's tools (slice 4).
8. Lint per folder (`npx eslint --max-warnings 0` on `src/shared`, `src/preload`, `src/main`, `src/renderer`, `cloud`, `e2e`, `scripts`); the full `npm run lint` runs out of memory. The full gate suite runs at most twice per slice. Node-heavy commands under `flock /tmp/mythscribe-heavy.lock`.
9. Each slice adds or updates its `docs/ARCHITECTURE.md` bullet, logs its open calls in `QUESTIONS.md` ("P3 slice n"), and notes its progress in the F-16.24/25/26 text. `src/main/ipc/handlers.ts` only registers channels; the logic lives in `src/main/scribe/` (new folder) and the existing memory modules.

**Build order:** slice 1 (Step 0, instant rules, evidence, the sheet-line store, the search-miss table, per-turn reasoning: data and pure rules, no prompt, no UI) → 2 (`agent.v9`: the one answer call, code quote checks, Self-Route, search misses, sheet writes) → 3 (`cite.v1`, scope checks, the one retry, Not found) → 4 (`navigator.v1` replaces `route.v2` in v2: routing kept, instant cards reach the chat) → 5 (the chat's UI: the instant card, the cited answer, steps and cost, the Ms Scribe switch, search misses) → 6 (offline replays, the live Ms Scribe run for the author, final verification). Each slice builds, gates and commits on its own.

**Coordination with other phases:**
- **P2b (done):** the instant "does A know X" / "who knows X" cards and the navigator's `knows` and `timeline` tools call P2b's functions (`storedKnows`, `threadsAsOf`, `storyYears`, `ageAsOf`, `sheetMemory`), positive lines only (rule 5).
- **P4:** adds "an open finding" to the instant card's contested test (`contested()` in `instant.ts`, slice 1) and *Ask Ms Scribe* on Needs a look's loose ends, which sends the loose end's text as a question through `ai:navigate`. Until P4, a value is contested by incompatible values or a stale claim only. `continuity` routes keep answering through Ms Scribe (`routeForMemory`, P1).
- **P5:** Try chats run `agent.v9` with turn kind `whatIf` (reasoning low) and are never read into memory; `agent.v9:try` and `agent.v9:version` stay planned rows.
- **F-16.31 (switch-over):** deletes `route.v2`/`agent.v8`/`query.v4` and the v1 branches; P3 leaves them untouched for v1.

## 0. The shape of it

```
chat message (v2) ─► ai:navigate
   localRoute (an action id typed: no request) ─► route result
   Step 0 (local, <50 ms): E0 the whole open scene · records the question names (state, knows, threads, age)
                           · FTS5 hits over every labelled source · the evidence menu (E1…En)
   instant? (record+slot / does A know X (yes only) / who knows X; live, uncontested)
       └─ unread changed sentence names the record + slot cue? ─► readNow (~0.1¢) ─► instant again
       └─► InstantCard (no AI call)                         stale / contested ─► lookup turn (no navigator)
   navigator.v1 (fast, ≤3 steps, ≤150 out each): classify (route.v2's actions + turn kind), then
       search(terms) · cards · read · state · knows · timeline · ideas · outline · todos ─► "use": [E…]
       └─ route action (editPass ask/line/…, rewrite, critique, betaReader, whatNext, synopsis, notes)
              ─► renderer dispatchRoute (unchanged: F-5.26 quick picks)
       └─ chat / query ─► answer, with the navigation (evidence keys, scope, search hits)
renderer ─► ai:agent { navigation } ─► runScribe
   agent.v9 (strong, one call; reasoning off / low by turn): rules → roster → history ≤1,500
       → voice (edit/draft) → E0 → labelled evidence → question
       ├─ {"need":"chapter 9"} once ─► ≤8k widened evidence ─► agent.v9 again ─► search misses logged
       └─ answer with [E7 "quote"] ─► code: quote in E7 as sent? · sentences naming a record without one: "not checked"
            ─► cite.v1 (fast): cited sentences · ordinal/absence scope ─► main claim unsupported: retry once
            ─► else "Not found in the manuscript (I looked in …)"
   edits: the v2 manuscript edits (Auto/Ask/Plan unchanged) + pin (Pinned / Ideas / "Is this an idea or canon?")
```

## 8. Decisions this plan makes (decided by Claude, unconfirmed; logged in `QUESTIONS.md`)

- **P3-D1.** Two channels, main stateless between them: `ai:navigate` (Step 0, instant cards, the navigator) answers an instant card, a route action the renderer runs as today, or an answer turn with its navigation (stable evidence keys, the scope, the terms, the search hits); `ai:agent` then takes the navigation and re-resolves the keys against the book as it is. Main keeps no per-turn state.
- **P3-D2.** Instant cards answer only short questions (at most 12 words) naming one record and one slot cue from a closed table (fixed, lasting and transient slots and the detail labels), or one knower and one secret, or one secret; questions asking why, what if, or to change or save anything never get a card. Accumulating slots, kinship and relation go to Ms Scribe.
- **P3-D3.** A value is contested when a fixed slot holds another value that neither contains, or any claim of the record and slot as of now is stale; a value later in the book does not contest. P4 adds open findings.
- **P3-D4.** Read-first looks at the open scene and at most two scenes with unsettled reads, for finished unread sentences naming the record (or the secret's words) with a slot cue; it uses *Read now*'s path, so Use AI and the reading switch must allow it; otherwise the question goes to Ms Scribe, who reads the whole open scene anyway.
- **P3-D5.** A stale or contested lookup goes straight to `agent.v9` as a lookup turn with that slot's claims, live and stale, and their paragraphs as they read now; no navigator call (design Part 5's lookup row).
- **P3-D6.** The navigator's tools add `outline` and `todos` to the design's seven: structure edits and to-do questions still exist in v2, and `agent.v8` had both.
- **P3-D7.** The navigator's first step carries `route.v2`'s actions and edit fields with the same words, read by the same field readers and settled by `settleRoute`/`routeForMemory`; `localRoute` runs first. Every v1 route action that exists in v2 is kept, and F-5.26's quick picks are unchanged.
- **P3-D8.** For first, last, ever, never, how-many and knows questions, code makes the search cover every scene up to now (or the whole book when asked), in reading order; the answer's scope line comes from what code searched, never from `checkedUpTo` (P2b-D9 holds). The `knows` tool lists positive lines only.
- **P3-D9.** Every evidence item is citable except a card (a map); computed lines (years, ages) are citable and labelled "computed from your book".
- **P3-D10.** E0 is the whole open scene up to 12,000 tokens (about 9,000 words); a longer scene sends the 12,000 around the caret and says which paragraphs were left out. `agent.v9` has its own input budget (24,000) by prompt version, so `agent`'s 12,000 and every v1 request stay as they are.
- **P3-D11.** Reasoning per request: `AiRequestInput.reasoning` only ever lowers. Answer, lookup, idea and to-do turns go out with reasoning off; edit, draft and what-if turns with low, their `max_tokens` raised by 1,000.
- **P3-D12.** History: the newest two turns whole up to 400 tokens each, older turns cut to their first line (25 words), citations stripped, at most 1,500 tokens, oldest dropped first, labelled not citable.
- **P3-D13.** A sentence needs a citation when it names a record or a scene reference; without a kept one it is marked "not checked". Advice and questions back to the author need none.
- **P3-D14.** The main claim is the answer's first sentence (the rules ask for the answer first). It is retried once when it keeps no citation, `cite.v1` says no, or the scope check finds an earlier passage; then the answer is "Not found in the manuscript (I looked in …)", composed in code from the open scene, the cited scenes and the search.
- **P3-D15.** Self-Route: one `need` per turn, resolved to a chapter by number or title, a scene ref or a range; whole scenes in reading order up to 8,000 tokens. A search miss is a kept citation into the widened text at a paragraph the turn's searches did not return; `search_miss` keeps the newest 500.
- **P3-D16.** Sheet writes: the `pin` edit names a record, the author's words and a place (pinned, ideas, ask). A name that is no record (or a secret or thread), or a line the page already holds, is not offered, and the answer says so; the chat never creates records. Auto lands pinned and ideas lines at once with the confirmation and *Undo*; Ask waits for *Apply*; "ask" shows *Idea* / *Canon*, which is the click in Ask and Auto; Plan gets no edit list. Lines are written through `record:addLine` after a flush and the open page is reloaded; *Undo* removes the line only while it still reads as written and carries the turn's mark.
- **P3-D17.** New feature ids `navigator` and `cite`; in v2 `route` and `query` are hidden and `chat`/`query` actions are gated by `agent`; a v2-only **Ms Scribe** switch writes `agent`, `navigator` and `cite`. With the navigator off, a message is answered from Step 0's evidence, as v1's router off falls back to chat.
- **P3-D18.** In v2, `ai:agent` runs `runScribe`; `agent.v8`'s v2 branch goes, and its read helpers move into the navigator's tools (no parallel implementation).
- **P3-D19.** Chat turns gain lenient `card` and `scribe` parts; v1 turns and older rows parse unchanged.
- **P3-D20.** The live Ms Scribe run's pass bars (§6.3).
- **P3-D21.** `cite` joins `NO_REASONING_FEATURES` and `LOWEST_EFFORT_FEATURES` (a short JSON check on the fast tier; the design's list named the navigator).

## 9. Gates, ticks, docs, and what P3 does not do

- **Gates per slice:** typecheck, lint per folder, test, test:e2e (`memory.spec.ts` and the unedited smoke), eval:ai. Slices 2, 3 and 4 run `eval:ai -- -u` and quote the token-report diff. No live run is possible here; the live Ms Scribe run and live fidelity are built for the author (§6.3).
- **Ticks:** none in slices 1–5 (progress notes in the F-16.24/25/26 text); all three after slice 6's final verification.
- **Docs in the same commits:** `docs/ARCHITECTURE.md` (one bullet per slice), `docs/AI-COST-REGISTRY.md` (slices 2–4), `QUESTIONS.md` (each slice's calls), `FEATURES.md` progress notes, `CLAUDE.md` "Next up" and `docs/OPERATOR-SETUP.md` (slice 6).
- **Not in P3:**
  - contradictions, open findings in the instant card's contested test, underlines, *Check the book*, loose ends with *Ask Ms Scribe* (P4);
  - Try chats, Versions, what-if turns outside the main chat (P5; `agent.v9` already takes turn kind `whatIf`);
  - embeddings (P8, F-16.35: only if the search-miss log justifies them);
  - deleting `route.v2`, `agent.v8`, `query.v4` and the v1 branches (the switch-over, F-16.31).
- **Risks:**
  - **The navigator costs more than the router for edit requests** (≈ 0.06¢ against ≈ 0.01¢). It is still small, and the prefix is cached. If the live run shows routing is no better, step 1 could run on the tail alone; that change would be a new version.
  - **FTS with synonyms can miss implied moments** (risk 12 in the design). Self-Route and the search-miss log measure this, and F-16.35 waits on that number.
  - **Strong-model answers may drop citations.** The code check and `cite.v1` catch it, and the retry costs one more Pro call. The live run reports the rate; if it is high, the rules get a new version, never a silent change.
  - **Long scenes make every answer dearer** (E0 is whole by answer 10). The ledger shows it per turn; P3-D10 caps the worst case.
  - **Slice 2 is the largest.** Its fallback is written in §2.7.
