# Story memory for a 100k+ word manuscript: web research and recommended architecture

**Caveat on sources:** the egress proxy refused direct fetches of arxiv.org, openrouter.ai and api-docs.deepseek.com (403 or ENOTFOUND), so every figure below comes from search-engine summaries of the cited pages. DeepSeek prices in particular disagree between sources and need checking on the official page before anyone commits to numbers.

## 0. Price baseline (DeepSeek through OpenRouter)
- **V4.1 Flash** (released 2026-09-10; the old `deepseek-v4-flash` ID routes to it):
  - Off-peak, per 1M tokens: about $0.15 input on a cache miss, about $0.003 on a cache hit, $0.60 output. Peak hours cost double. ([benchlm](https://benchlm.ai/deepseek/api-pricing), [yottalabs](https://www.yottalabs.ai/post/deepseek-v4-1-flash-pricing-specs-v4-pro-routing-2026), [orcarouter](https://www.orcarouter.ai/blog/deepseek-v4-1-flash-pricing))
  - Older V4 Flash pricing was $0.14 miss / $0.0028 hit / $0.28 output ([eesel](https://eesel.ai/blog/deepseek-v4-flash-pricing)).
- **V4 Pro:** sources disagree. Cache-miss input is quoted at $0.435 (promotional), $1.32 (peak) or $1.74 (list). Cache-hit input is quoted at $0.0036 to $0.044. ([cloudzero](https://www.cloudzero.com/blog/deepseek-pricing/), [puter](https://developer.puter.com/tutorials/deepseek-api-pricing/))
- **How caching works:**
  - DeepSeek caches automatically and on a "best effort" basis. A request only gets the discount on a full match with a stored prefix unit ([apisrouter](https://apisrouter.com/deepseek-v4-context-caching)).
  - OpenRouter keeps sending follow-up requests to the same provider after an implicit cache hit, including for DeepSeek. That stickiness turns off if the request sets `provider.order` ([OpenRouter docs](https://openrouter.ai/docs/guides/best-practices/prompt-caching)).
- **Context window:** both models take 1M tokens ([datalearner](https://www.datalearner.com/en/ai-models/pretrained-models/deepseek-v4-pro)).

## 1. Seven approaches compared

| Approach | Accuracy evidence | Token cost profile | Fit |
|---|---|---|---|
| **Long-context dump** (about 130k tokens for 100k words) | Weak on novels. NoCha: best model scored 55.8% on true/false claim pairs about whole books; open models were at chance; world-building-heavy fiction was worst ([EMNLP'24](https://aclanthology.org/2024.emnlp-main.948)). NoLiMa: at 32K tokens, 11 of 13 models fell below 50% of their short-context baseline ([ICML'25](https://proceedings.mlr.press/v267/modarressi25a.html)). Chroma "context rot": all 18 models tested got worse as input grew, more so with related distractors, which describes a manuscript well ([Chroma](https://research.trychroma.com/context-rot)). NovelQA: best model 62.3% ([ICLR'25](https://mlanthology.org/iclr/2025/wang2025iclr-novelqa)). | Flash cache miss is about $0.02 per call; a cache hit is about $0.0004. Pro is about $0.06–0.23 per call on a miss. **Each manuscript edit invalidates the cached prefix from that point on**, so an author who is actively writing rarely gets hits. | Only as a fallback on explicit request. Never use it as the memory system. |
| **Retrieval vs long context** | Long context beats RAG on average when cost is no object. "Self-Route" answers from retrieved chunks first and escalates to full context only when the model says the chunks are not enough; it matched long-context quality at much lower cost ([Li et al. EMNLP'24](https://arxiv.org/abs/2407.16833)). On NovelQA, GPT-4 with retrieval scored 67.89 at $52.8; full novel in context scored 67.81 at $99.8 ([AI Agents That Matter](https://arxiv.org/pdf/2407.01502)). | Retrieval costs about 5–15k tokens per query. | Core of the design. |
| **Hierarchical summaries** (scene → chapter → book) | RAPTOR (a tree of summaries) plus GPT-4 improved QuALITY by 20 points; querying several tree layers scored 73.7 vs 57.9 for leaf chunks only ([RAPTOR](https://arxiv.org/pdf/2401.18059)). BooookScore: merging summaries hierarchically is more coherent; updating one summary incrementally keeps more detail ([ICLR'24](https://iclr.cc/virtual/2024/poster/19359)). Warning: summaries written by an LLM contain more plot holes than the source (+50%) ([FlawedFictions](https://arxiv.org/abs/2504.11900)). | One Flash call per scene, then one roll-up call per chapter only when its scenes change. | Keep, but use summaries as a **navigation layer**, never as the source of canon. |
| **Hybrid retrieval** (BM25 keyword + embeddings) | Anthropic's contextual retrieval: embeddings cut top-20 retrieval failure by 35%; adding BM25 brought the cut to 49%; adding a reranker brought it to 67% ([summary](https://www.maginative.com/article/anthropics-contextual-retrieval-technique-enhances-rag-accuracy-by-67)). SQLite FTS5 plus sqlite-vec combined with reciprocal rank fusion (RRF) is a proven pattern ([Willison](https://simonwillison.net/2024/Oct/4/hybrid-full-text-search-and-vector-search-with-sqlite/)). | **Free if local.** EmbeddingGemma: 308M parameters, under 200MB RAM when quantized, 2K-token input, vectors can be cut from 768 to 128 dimensions ([Google](https://developers.googleblog.com/en/introducing-embeddinggemma/)). Qwen3-Embedding-0.6B: MTEB multilingual 64.3 ([dev.co](https://dev.co/ai/llms/qwen3-embedding-0-6b)). | Strong fit. MythScribe already has the BM25 half: FTS5 at `src/main/search/passageIndex.ts:102`. `src/main/ai/context/queryContext.ts:26-33` notes it does no embedding retrieval yet. |
| **Entities and aliases without tags** | Novelcrafter's Codex detects entries by name plus aliases: case-insensitive, automatic plurals, an exclusion list, and a per-entry choice of sending to the AI "always / when detected / never". No manual tagging ([docs](https://www.novelcrafter.com/help/docs/codex/codex-mentions)). BookNLP is reliable on names (0.85 name recognition, 0.99 clustering) but weak on pronouns (about 0.77) ([arXiv 2307.03734](https://arxiv.org/pdf/2307.03734)). GLiNER2 (about 205M parameters, runs on CPU) reportedly scores near GPT-4o on zero-shot entity recognition: 0.590 vs 0.599 F1 ([pioneer](https://pioneer.ai/blog/gliner-modern-named-entity-recognition)). | Alias scan is free. Discovering new names costs nothing extra if folded into the per-scene extraction call. | Match aliases deterministically and link entities at **scene level**. Skip pronoun coreference. MythScribe already has `src/main/tag/scanMentions.ts`, but aliases currently live on tags (`src/main/entity/entityStore.ts:83`). |
| **Knowledge graphs and agent memory** | RAG vs GraphRAG: the two are complementary. Graphs win multi-hop questions; plain RAG wins detail lookups. Graphs cost more to build and are slower to query ([arXiv 2502.11371](https://arxiv.org/abs/2502.11371)). LightRAG merges new data into its graph by union; GraphRAG rebuilds its communities ([LightRAG](https://arxiv.org/html/2410.05779v3)). Zep/Graphiti stores a validity window on each fact (`valid_at`/`invalid_at`); DMR 94.8 vs 93.4; temporal reasoning 36.5 → 54.1, but knowledge-update dropped 76.9 → 74.4 (vendor numbers) ([paper](https://arxiv.org/abs/2501.13956), [blog](https://blog.getzep.com/state-of-the-art-agent-memory/)). Each Graphiti "episode" triggers several LLM calls ([docs](https://docsearch.algolia.com/mcp/docs/repo/getzep/graphiti)). Mem0 reports about 7k tokens per call vs 25k+ for full context (vendor) ([mem0](https://mem0.ai/research)). Letta's "sleep-time" agent edits memory off the critical path ([Letta](https://letta.com/blog/sleep-time-compute)). | GraphRAG-style building is expensive. A per-edit episode pipeline means N LLM calls per scene save. | Take the **ideas**: facts with validity windows and background memory editing. Do not adopt a graph database or community summaries. |
| **Continuity checking** | FlawedFictions: frontier models struggle to find plot holes; accuracy falls with story length; more reasoning did not help ([arXiv 2504.11900](https://arxiv.org/abs/2504.11900)). Systems that track structured story state do better: SCORE, which uses state tracking plus RAG, reports large gains in item-status tracking (self-reported) ([SCORE](https://arxiv.org/html/2503.23512v6)). NstAgent tracks state over stories of 10–100K words ([papers.cool](https://papers.cool/arxiv/2609.35759)). | Checking the whole book in one prompt is expensive and inaccurate. Checking pairs of conflicting facts is cheap. | Find candidate contradictions deterministically, then ask the LLM to judge each pair with both quotes in front of it. |
| **Verification** | SafePassage: reject any extraction whose quote is not in the source, then check entailment; up to 85% fewer hallucinations ([arXiv 2510.00276](https://arxiv.org/html/2510.00276v1)). LangExtract records character offsets and an alignment status of exact, fuzzy or not found ([Google](https://developers.googleblog.com/en/introducing-langextract-a-gemini-powered-information-extraction-library/)). Chain-of-Verification (CoVe) reduces list and long-form hallucination ([arXiv 2309.11495](https://arxiv.org/pdf/2309.11495)). | A quote check is free. CoVe and self-consistency multiply cost 2–5×. | Check every quote in code. Reserve extra LLM verification for writes into canon. MythScribe already drops AI facts whose quote has left the scene (`src/main/entity/factStore.ts:24,521`). |
| **Incremental indexing** | Jigsaw-LightRAG marks each document new, modified, unchanged or deleted, extracts only the changed ones and reuses the rest; it reports large token savings ([preprints](https://www.preprints.org/frontend/manuscript/a1f65d9e81808a8f55f50d249f585994/download_pub)). LightRAG deletes by tracing which chunks each fact came from ([commit](https://huggingface.co/spaces/rm-lht/lightrag/commit/27a07994af08a43715bd6fc043434fbc4c7fc95b)). | Cost tracks how much was edited, not book size. | MythScribe already hashes each scene's content (`src/main/ai/summarize.ts:147,209`). Go finer: hash per paragraph for the free layers. |

## 2. Recommended architecture

**Principle:** the prose is the only canon. Every derived fact points back to a verbatim quote, and anything that cannot be re-found in the text expires on its own. The author never maintains anything by hand.

1. **L0, text:** the manuscript split into paragraphs, each with a stable ID, its scene position and a content hash.
2. **L1, free and instant (local, on every save):**
   - Re-index only paragraphs whose hash changed, in FTS5 BM25 and in sqlite-vec using a local embedding model (EmbeddingGemma or Qwen3-0.6B via onnxruntime in a worker).
   - Run a deterministic alias scan that maps paragraphs to entities.
   - Retrieval merges the keyword and embedding results with RRF, then boosts the scene the author is working in and the entities named in the question.
3. **L2, cheap (Flash, one structured call per changed scene, in the background when the author is idle):**
   - Output: a scene card of about 100 tokens (POV, place, story time, beats), entity mentions plus any new names or aliases proposed, and facts as `(entity, slot, value, quote)`.
   - Quotes are checked in code; a fact whose quote is not found is discarded.
   - Skip the call entirely when the changed paragraphs contain no alias hits and the diff is under a threshold.
   - Facts whose quote still exists survive edits without another call.
   - Rough cost: about $0.0007 per scene on Flash off-peak, so **about $0.03–0.08 to index a whole 100k-word book once**.
4. **L3, derived and mostly deterministic:**
   - **Automatic progressions:** "state as of scene N" is the latest fact in each slot whose source scene is at or before N. Novelcrafter offers the same thing as manual progressions ([docs](https://docs.novelcrafter.com/en/articles/8675593-progression-additions)); here they come from extraction.
   - Two facts that disagree in the same slot become a To do candidate, which a Flash or Pro call then judges with both quotes in view.
   - Chapter and book summaries are rolled up lazily from scene cards and cached by the hash of their children.
5. **L4, query router (Self-Route):**
   - Lookups ("what colour are Mara's eyes?") are answered from L3 plus the quote, with no LLM call or one Flash call.
   - Open questions get a stable cached prefix (rules, voice, the core bible), then hybrid top-k passages, scene cards and entity state, about 10–15k tokens in total. That is roughly $0.002 on Flash and $0.005–0.025 on Pro. Citations are checked in code.
   - If the model reports the context is insufficient, widen the context to the full chapter.
   - Whole-book context only on an explicit request.

**Tags:** for AI memory, manual tags can go. Mention detection is better served by an entity registry with automatic aliases plus extraction. Removing them means moving aliases from tags onto entities (they currently come from tags, `entityStore.ts:83`). Author-chosen labels can stay as an optional organising tool.
